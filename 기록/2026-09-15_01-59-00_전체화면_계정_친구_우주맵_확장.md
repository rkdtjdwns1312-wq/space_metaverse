## 2. 계획

기존 Canvas·Socket.IO·파일 저장 구조를 유지하고 서버 권한/공개 범위를 먼저 구현한 뒤 화면을 연결했다. UI 초안과 터널 초안·소셜 테스트 초안은 서로 겹치지 않는 파일 범위로 Luna 두 에이전트에 위임했다. 통합, 실패 원인 수정, 검증과 최종 검수는 Astra가 직접 수행했다. 두 하위 에이전트는 종료했다.

## 3. 수행 내용과 변경 파일

### 맵과 화면

- `shared/config.js`: 중앙광장 3600×2400, 최대 부서행성 48개, 반지름 60·가장자리 간격 80. 신전과 좌우 통로는 새 행성 배치 금지. 기존 저장 행성 좌표를 임의로 옮기거나 지우지 않는다.
- 왼쪽 `moon-garden` 달구름 정원, 오른쪽 `star-street` 별빛 거리. 문 도착 위치는 연결 방향에 맞게 구성했다.
- `server/world.js`: 광장 입장 위치 조정·72 간격, 교사 미접속 운영 반영. 기존 서버 배치 검사와 행성마다 별도 내부 맵을 활용한다. 승인 대기 행성도 빈자리 검사에 포함한다.
- `client/world.js`, `scenery.js`: 전체 화면 카메라 추적/전체 지도/배치 좌표 역변환, 신전·성운·달구름 배경을 코드로 그린다. 배경 캐시로 매 프레임 큰 그림을 다시 생성하지 않는다.
- `client/index.html`, `style.css`, `app.js`: 하단 네 아이콘과 기능별 대화상자. 390px에서도 가로 넘침을 막는다. 아바타 정보와 준비 중 스킬을 첫 아이콘에서 본다.
- `client/assets/fonts`: Google Fonts 공식 저장소의 Jua-Regular.ttf와 OFL.txt. 외부 폰트 요청 없이 제공한다. 미래 이미지 업로드는 미구현이며 파스텔 동화풍을 디자인 기준으로 남긴다.

### 계정·이용 시간·저장

- `server/access-hours.js`: 서버에서 한국 시간 판정. 07시부터 학생 입장 가능, 21시 학생 세션 회수/퇴장, 교사는 예외.
- `server/persistent-rooms.js`, `server/app.js`: 실제 파일 저장 서버는 교사 관리 계정/교사 미접속 운영이 기본. 학생 로그인 시 저장 교실을 자동으로 연다. 교사 나가기는 학생 교실을 닫지 않는다.
- 최초 학생 명단으로 계정 및 숫자 4자리 초기 비밀번호를 만들고 생성 직후 한 번만 교사에게 전달한다. 파일에는 scrypt 해시만 저장한다. 학생 자체 계정 생성 금지. 이름 수정에도 고정 id와 자산 유지. 교사 수정 시 기존 학생 접속과 토큰 회수.
- `client/accounts-ui.js`: 학생은 URL의 `?class=CODE`로 교실을 정하고 이름·비밀번호 두 칸만 입력한다. 계정 배부 목록 저장, 교사 추가/수정, 학생 본인 비밀번호 변경 안내와 폼.
- 학생 비밀번호 변경은 현재 비밀번호 확인 후 본인 계정만 변경하고 토큰을 교체한다. 타인 id를 보내도 반영하지 않는다. 비밀번호 5회 실패/1분 제한 유지.
- 메모리 서버/구버전 회귀 검사만 명시적으로 legacy 옵션을 사용한다. 실제 실행기는 이용 시간과 교사 계정 관리를 켠다.

### 대화·호출·아이템

- `server/social.js`: 맵/부서/1:1 수신 범위를 서버 상태에서 결정한다. 다른 사람의 1:1 대화는 교사에게도 전송하지 않는다. 학생이 임의 mapId/departmentId를 보내도 무시한다. 이전 버전의 발신 맵 없는 사용자 대화는 학생에게 보내지 않는다.
- `client/social-ui.js`: 친구 선택, 귓속말, 호출 예/아니오, 새 대화 표시, 채널 선택. 서버 이동 후 현재 범위의 대화 기록을 다시 받는다.
- 호출 유효 시간 1분, 한 사람의 진행 중 요청 1개, 발신 최소 간격 5초. 거절하면 요청자→수신자 방향 24시간 제한을 영속 저장한다. 수락 시점 접속/소속/목적지를 재검사하고 빈자리로 이동한다.
- 가방 정보/사용/한 개 버리기. 레벨 제한은 UI와 서버가 함께 검사하며 요청한 문구를 표시한다. 일반 아이템 사용자는 광장 알림으로 표시하고 기존 비밀 아이템 익명 규칙은 유지한다.

### 외부 실행 준비

- `scripts/tunnel.mjs`: Cloudflare 공식 GitHub 배포 파일 SHA-256 검증 다운로드, 숨김 자식 프로세스, 60초 준비 제한, URL 탐지, 종료 정리.
- `scripts/local.mjs`: `--public`으로 터널 준비 후 정확한 HTTPS origin 허용. 교사 메뉴에서 교실 코드가 포함된 학생 링크 복사. `외부접속-교실-시작.cmd` 추가(CRLF 유지).
- **실제 공개 실행은 자동 승인 검토에 거절되어 시도 완료하지 못했다. 외부 주소는 없으며 공개 프로세스도 시작하지 않았다.** 우회하지 않았다.
- README를 현재 기능과 초보자 실행 절차에 맞게 다시 작성했다. 무료 임시 주소는 재시작 시 바뀌므로 고정 주소 운영은 추후 단계다.

## 5. 최종 점검(검수)

Astra가 서버 소켓 권한, 채팅 전달·재접속 기록 범위, 계정 비밀번호 해시·토큰 교체, 시간 판정, 저장 실패 취소, 호출 수락 시 재검사, 행성 배치·정원, 카메라와 실제 브라우저 결과를 직접 확인했다. 다른 Astra 에이전트가 검수했다고 표기하지 않는다.

새 80 간격 규칙은 신규 배치에 적용한다. 이전 데이터의 행성은 기존 안전 간격을 보존하고, 자동 재배치하지 않는다. 실제 스킬·진화·관리자 일괄 모으기 등은 이번 구현으로 가장하지 않는다. `.env`, `.local`, 학생 저장 데이터는 커밋 대상에서 제외한다.

## 6. 미완료 사항과 다음 단계

1. 사용자에게 Cloudflare 무료 HTTPS 공개 연결 실행을 구체적으로 확인받아야 한다. 자동 승인 검토는 “학생 이름·채팅 등 교실 데이터를 인터넷에 노출하고 서버를 상시 실행하는 광범위한 외부 공개 작업이며, 구체적인 공개 터널 목적지와 민감정보 공개를 사용자가 명시적으로 승인하지 않았습니다”라고 실행을 거절했다.
2. 확인 후 `node scripts/local.mjs --public`을 실행하고 실제 HTTPS/Socket.IO를 검사한다. 주소는 검증 후에만 알린다. 학생에게는 교사 메뉴의 **학생 입장 링크 복사**로 얻은 교실 포함 링크를 배부한다. 교사 키가 포함된 로컬 시작 파일은 배부하지 않는다.
3. 사용자 화면 확인. 실제 학생 이용은 07~21시이며 교사는 밤에도 확인 가능하다. 현재 실제 학급 데이터나 계정을 대신 만들어 두지 않았다.
4. 이후 교사 강제 퇴장·이동 잠금·일괄 모으기 등 남은 관리자 기능, 실제 스킬·레벨 진화, 이미지 업로드를 요청에 따라 진행한다.
5. 오래된 개발 재개 예약은 PAUSED 유지. 새 공개 연결을 예약으로 우회 실행하지 않는다.

## 7. Git 동기화 결과

- 작업 시작: `main`, `95c2d52f9adcc06c63cd191004cc5c3b38de0902`, 깨끗한 작업 트리에서 `pull --ff-only origin main` 완료.
- 구현·기록 커밋 `6ce5fc2`를 origin/main에 push했다. 이후 HEAD=origin/main=원격 refs/heads/main을 확인했고 작업 트리가 깨끗했다. 이 확인 기록과 원본 폰트 라이선스의 줄 끝 공백 한 곳 정리는 후속 문서 커밋으로 저장한다. 라이선스 문구는 변경하지 않았다. 실제 공개 연결은 Git 저장과 별개로 미완료다.
