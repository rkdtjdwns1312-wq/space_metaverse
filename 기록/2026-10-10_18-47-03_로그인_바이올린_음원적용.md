# 로그인 화면 바이올린 음원 적용

- 작업 도구/모델: Codex GPT-6 (앱에 세부 모델명 미표시)
- 최종 검수 모델: gpt-6-astra
- 범위: 요청 455 (요청 454 미리듣기 후 사용자의 적용 선택)

## 1. 요청 요약

사용자가 미리 듣고 선택한 바이올린을 로그인 화면 음악 전체에 적용한다. 원곡은 보존하고 반복 재생·음량·음소거를 확인한다.

## 2. 계획

승인된 첫 1분의 바이올린 음색을 곡 전체로 확장하고, 브라우저의 원곡 재생 길이에 맞춘다. 로그인 화면에서 원곡과 함께 재생하되 다른 맵에서는 함께 정지시킨다.

## 3. 변경 내용·파일

- `client/assets/audio/login-violin-layer.wav`: 167.588083초, 12kHz·16bit·스테레오 바이올린 레이어. 승인된 첫 60초 선율을 유지하고 이후 곡의 분석에 맞춰 이어간다. 원본 `login-in-front-of-love.mp3`는 변경하지 않았다.
- `client/audio.js`: 로그인 원곡과 레이어를 함께 반복 재생한다. 시간 차이가 커질 때 위치를 맞추고 원곡 대기·재개, 맵 이동, 음량·음소거·정지에 레이어를 연동한다.
- `tests/audio-maps.test.js`: 재생·전환·시간 동기화·버퍼링·음량·음소거·정지의 회귀 검사를 보강했다.
- 전체 음원 생성·브라우저 확인용 임시 스크립트와 원시 오디오는 비공개 `.local/`에만 두었다.

## 4. 검증

- `node --test tests/audio-maps.test.js`: 1/1 통과.
- 실제 Edge에서 두 음원의 재생 길이 167.5881초/167.588083초, 로그인 재생, 반복 뒤 시간 차이 약 0.001초, 음량 60%·음소거 연동 확인.
- 원본 MP3의 브라우저 재생 길이가 단순 디코딩 길이보다 약 0.14초 짧아, 레이어 길이를 브라우저 기준에 맞춘 뒤 반복 검사를 통과했다.

## 5. 최종 검수

gpt-6-astra 검수에서 원곡 버퍼링 중 레이어가 앞서갈 위험을 발견해 대기·재개 연동과 테스트를 추가했다. 재검수에서 해당 문제가 해결됐고 추가로 유의미한 문제를 발견하지 못했다. 검수는 보고된 단위 검사와 Edge 재생 결과도 함께 참고했다.

## 6. 미완료·다음

없음. 레이어 WAV는 약 8MB이므로 최초 로그인 음악 다운로드량이 그만큼 늘어난다.

## 7. Git

시작 시 Git 상태 확인과 `git pull --ff-only origin main` 완료. 사용자 원본 `몬스터 디자인/`과 `.local/` 파일은 제외하고 코드·검사·레이어·기록·메인만 선별 커밋할 예정이다. push 및 실제 원격 SHA 확인 결과는 최종 답변에 보고한다.
