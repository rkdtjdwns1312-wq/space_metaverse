## 1 요청 요약

198: 선생님은 조합기에 상호작용해 LV2/LV3/LV4 탭으로 모든 조합법을 볼 수 있게 한다. 학생에게 비밀인 기존 원칙은 유지한다.

199: 오색별빛 쉼터 네 번째 연산게임을 제거하고 스도쿠 하6×6·중9×9·상12×12로 교체한다.

## 2 계획

교사 세션을 확인하는 읽기 전용 서버 API → 교사 버튼/레벨 탭 → 학생 접근 차단 검증. 이후 유일한 정답의 스도쿠 생성기 → 숫자 입력 UI → 기존 오락기 교체 → 새 게임과 기존 지도/저장 회귀 검사 → 서버 반영·문서·Git 저장.

## 3 수행 내용과 변경 파일

- `server/app.js`: `crafting:recipes` 읽기 전용 이벤트. 서버 세션 교사권한, 실제 접속, 조합기 근접/맵/이용 상태, 숫자 레벨2/3/4를 검증한다. 선택 레벨의 완성품과 재료 수량만 요청한 교사에게 응답한다. 정적 공개 파일이나 방 방송에는 넣지 않는다.
- `client/crafting-ui.js`, `client/crafting.css`: 선생님 조합법 보기, LV2/3/4, 재료별 수량, 빈 목록, 닫기. 레벨 빠른 전환의 오래된 응답·닫기 뒤 응답을 버린다. 권한변경/로그아웃/닫기 때 이미 보였던 비공개 목록을 지운다. 조합 화면과 기존 기능 유지.
- 실제 비공개 목록은 격리 메모리 교실에서 LV2 9개/LV3 8개/LV4 0개를 확인했다. 실제 레시피 내용은 공개 테스트/문서에 옮기지 않았다. 수업 저장 파일을 검증에 사용하지 않았다.
- `shared/sudoku.js`: 행/열/작은구역별 숫자 규칙, 무작위 완성판과 유일해 확인 후 빈칸 제거. 6구역2×3·9구역3×3·12구역3×4. 탐색 상한 초과를 유일해로 잘못 판단하지 않는다. 중복/범위 오류와 완료 판정 분리.
- `client/sudoku-game.js`, `.css`: 난이도, 새 문제, 칸 선택, 숫자 단추/키보드1~9·A/B/C(10/11/12), 지우기, 화살표 이동, 고정 단서 보호, 충돌 색, 완성 축하, 닫기 때 이벤트/예약 작업 정리. 10~12도 화면에서는 숫자로 표기. 혼자 하는 연습이며 재화/순위/진행 영구저장은 추가하지 않았다.
- `client/arcade-ui.js`, `shared/config.js`: 네 번째 기기를 별빛 스도쿠로 교체. 기존 연산 UI/CSS/문제생성/전용테스트는 삭제, 역사 기록은 유지했다.
- `tests/crafting-teacher.test.js`, `tests/sudoku.test.js`, `scripts/verify-crafting.mjs`, `scripts/verify-sudoku.mjs` 및 README 갱신.
- Luna6(low)에는 교사 조회 테스트와 스도쿠 UI를 각각 별도 파일로 위임했다. 본체는 서버·생성기·연결·브라우저 검사·보완을 수행했다. 테스트 초안의 미등록 가짜 item ID를 카탈로그에 실제로 존재하는 ID의 합성 조합으로 바꾸고, 레벨은 출력 카탈로그에서 계산하도록 검증했다.
