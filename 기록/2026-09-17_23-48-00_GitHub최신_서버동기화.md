## 3. 수행 내용과 변경 파일

- 로컬은 9월 16일 저장본 f2173fa로, 원격 d8d13d1보다 9커밋 뒤처져 있었다. 작업 트리가 깨끗한 것을 확인한 뒤 `git pull --ff-only origin main`으로 53파일을 갱신했다. 패키지 정의·잠금 파일 변경은 없었다.
- GitHub에 저장하는 것만으로 다른 PC 서버가 자동 갱신되지 않는 것이 확인된 차이의 원인이다. 이 PC에서는 3000 포트 서버와 공개 실행기가 꺼져 있었고 학생 링크 파일도 이전 주소였다. 다른 PC의 서버 상태나 과거 URL의 실제 제공 내용까지 확인한 것은 아니다.
- `node scripts/local.mjs --public`을 숨김 창으로 실행했다(PID2520). 종료가 확인된 이전 저장소 잠금만 실행기가 복구했다. 데이터 삭제·초기화 없이 공개 서버가 시작되었다.
- 현재 공개 주소: https://farm-threats-berry-choices.trycloudflare.com/ ; 로컬 주소: http://127.0.0.1:3000/ . 교사 메뉴에서 학생 입장 링크를 다시 복사해 배부한다.
- `scripts/verify-object-growth-maps.mjs`: 블랙홀 추가로 맵이 8개인데 기존 검사가 7개를 기대해 실패했다. 실제 정적 맵 목록의 개수를 기준으로 검사하도록 수정했다. 앱 코드는 추가 변경하지 않았다.
- `교실컴퓨터에서_이어서작업.md`: Luna/low에 문서 수정만 위임했다. 최신 기록을 찾는 인계 문장과 pull→서버 재실행→새 주소 배부 순서, 데이터·키가 Git 동기화 대상이 아니라는 안내를 보강했다. 본체가 검토했다.
- `메인.md`: 요청 094와 최신 PC 실행 상태를 반영했다.

## 4. 검증 결과

- `node --test tests/*.test.js`: 200/200 통과.
- `node scripts/verify-browser.mjs`: 기본·저장 89개 통과, 오류 없음.
- 추가 브라우저: new-ui 12, navigation 15, department-work 6, object-growth-maps 7, homework 5, warnings 5, interior-decor 3개 통과. 모두 별도 테스트 서버·테스트 자료를 사용했다.
- 공개 `/health` 응답은 정상이며 persistent=true, publicOrigin이 새 주소와 일치했다. 공개 WebSocket 연결 성공 후 연결을 종료했다. 공개 인증 검증에 교사 키나 학생 비밀번호를 사용하지 않았다.
- 공개 config.js·world.js·app.js·temple-ui.js·assignment-ui.js·warning-ui.js·interior-decor-ui.js·style.css의 SHA-256 해시가 로컬 최신 파일과 모두 일치했다.
- 실제 Edge 브라우저에서 공개 로그인 화면 HTTP200, 제목·입장 버튼 및 스크린샷을 확인했다. 브라우저 연결 표시도 `우주와 연결되었어요`가 되는 것까지 확인했다. 첫 `networkidle` 대기는 시간 초과가 있었지만 문서 로드 완료(`domcontentloaded`) 및 연결 표시 기준 재검사는 정상 완료했다. 지속 연결이 있는 앱의 무통신 상태를 배포 완료 조건으로 사용하지 않았다.
- 실행 로그 오류 없음. `git diff --check` 통과. 검증 로그와 로그인 스크린샷은 Git 제외 폴더에 보관했다.
