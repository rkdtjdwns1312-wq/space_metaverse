# 학생 입장 QR과 이 PC의 외부 접속 준비

- 날짜: 2026-10-25 KST
- 작업: 학생용 입장 링크를 QR 이미지로도 공유하고, 이 컴퓨터에서 교실 서버를 열어 외부 학생 접속을 준비한다.

## 적용 내용

- 교사 메뉴의 교실 코드 옆에 `QR 코드 복사`를 추가했다. 누르면 학생용 링크가 들어 있는 QR 이미지가 클립보드에 복사되고, 미리보기에서 다시 복사하거나 PNG로 저장할 수 있다. 모바일 카메라로 읽으면 교실 코드가 미리 채워진 입장 화면을 연다.
- 브라우저 안에서 QR을 생성한다. 외부 QR 생성 API로 링크를 보내지 않는다. QR 생성기는 MIT 라이선스의 `qrcode-generator`를 프로젝트에 포함하고 라이선스와 출처를 함께 보관한다.
- HTTPS 공개 주소와 6자리 교실 코드만 공유 대상으로 허용한다. 로컬·사설 IP, 교사 자격 정보, 다른 쿼리 매개변수와 URL 조각이 들어간 주소는 복사하지 않는다. 기존 학생 링크 복사에도 같은 공개 주소 검사를 적용했다.
- 비공개 교실 저장 파일 2개를 `.local`에 백업하고 SHA-256 일치를 확인했다. 비공개 `.env`의 테스트용 `STUDENT_HOURS=false`를 운영용 `true`로 변경했다. 이 파일·백업·학생 정보는 Git에 포함하지 않는다.

## 검증

- QR 관련 단위 2건, 기존 학생 계정 관련 4건: 모두 통과.
- 설치된 Edge를 이용한 실제 교사 메뉴 중첩 화면 검사: 링크 텍스트 복사, QR PNG 클립보드 복사, QR 미리보기, 로컬 링크 거부가 통과했다. 생성된 PNG는 5,853바이트였다. Edge 시험 환경에 QR 스캔 API가 없어 카메라 스캔 자체는 이번 자동 검사 범위 밖이다.
- 초기 검증 당시 이 PC의 `http://127.0.0.1:3000/health`는 정상 응답하고 지속 저장이 활성화됐다. `.env`, `.local/teacher.html`, `data/classes/`의 HTTP 요청은 404였으며 공개 주소는 아직 없었다. 이후 승인 후 공개 검증은 아래에 기록했다.
- 작업 전 `git pull --ff-only`로 최신 상태를 확인했다. 기존의 별도 HWP 삭제 상태와 `몬스터 디자인/` 미추적 폴더는 건드리지 않는다.

## 최종 검수

`gpt-6-astra(high)` 읽기 전용 검수에서 끝에 점이 붙은 로컬 호스트, 사설 IPv6, 링크 로컬 IPv4를 거부하지 않는 경계 문제(P2)를 발견했다. 도메인 이름만 허용하도록 보완하고 해당 사례를 테스트에 추가했다. 단위 검사를 다시 통과했고, 응답 지연을 포함한 Edge 브라우저 검사도 다시 통과했다. 같은 Astra 검수자가 수정 결과를 재확인하여 **최종 PASS**를 보고했다. 전체 게임 기능은 변경하지 않아 관련 계정·QR 검사와 대표 브라우저 흐름으로 검증을 한정했다.

## 외부 연결 상태

Cloudflare Quick Tunnel(`*.trycloudflare.com`)을 통해 이 PC의 `127.0.0.1:3000`을 공개 HTTPS 주소에 연결하는 첫 실행은 자동 승인 검토가 **거부**했다. 이유는 구체적인 외부 목적지와 통과하는 교실 데이터 범위에 대한 승인 부족이다. 우회 실행하지 않았다. 외부 연결 시 공개 화면·게임 리소스뿐 아니라 학생이 입력하는 교실 코드·계정 정보와 채팅·활동 데이터가 Cloudflare 경유 연결을 통과한다.

같은 날 후속 요청에서 임시 공개를 다시 진행했다. Cloudflare 연결 포트 7844는 통과했으나, 공개 모드 프로세스 시작이 자동 승인 검토에서 같은 이유로 재차 거부됐다. 기존 로컬 서버를 중지한 상태였으므로 즉시 로컬 전용으로 재시작했고, `/health` 정상·`publicOrigin` 비어 있음을 확인했다. 임시 주소와 통과 데이터 범위를 명시한 사용자 승인 질문을 보냈으며, 답변 전에는 외부 공개를 다시 시도하지 않는다. 이 후속 요청에서 게임 코드·자료는 바꾸지 않았다.

## 명시적 승인 후 임시 공개

사용자가 목적지(`https://<임의문자>.trycloudflare.com`)와 교실 코드·계정 이름/비밀번호·채팅·게임 활동 데이터의 Cloudflare 경유 범위를 명시적으로 승인한 뒤 임시 공개를 실행했다. 공개 HTTPS의 `/`, `/health`, `/api/public-config`, Socket.IO 폴링은 200으로 응답했고 같은 출처 WebSocket이 연결됐다. `.env`, `.local/teacher.html`, `data/classes/` 요청은 모두 404였다. Edge에서 공개 주소의 학생 입장 화면을 열어 `?class=ABC234` 코드 자동 입력을 확인했다. 비동기 계정 설정이 끝나기 전 초기 검사에서는 코드 칸이 비었으나, 설정 완료를 기다린 실제 흐름에서는 정상 입력됐고 페이지 오류가 없었다.

로그인 화면은 오후 10시 종료라고 표시하지만 서버가 오후 9시에 학생을 내보내던 불일치를 발견했다. 기존 사용자 요청대로 서버·문구·관련 테스트를 한국 시간 07:00~22:00에 맞췄고 시간 경계 관련 서버 검사 11건을 통과했다. 이전 터널과 서버를 닫은 뒤 새 공개 주소로 재시작해 HTTPS 화면·비공개 경로·WebSocket·학생 화면을 재검증했다. 임시 주소는 Git에 포함하지 않는 `.local/student-link.txt`에만 보관한다. 학생에게는 교사 화면의 `학생 입장 링크 복사` 또는 `QR 코드 복사`로 해당 교실 코드가 들어간 주소를 배포한다.

이 PC의 전원·인터넷·서버·터널이 켜져 있는 동안에만 주소가 유효하며 재시작하면 주소가 바뀐다. Cloudflare 공식 문서는 고정 만료 시간을 제시하지 않지만 가동 시간도 보장하지 않는다. 이 PC에서 Cloudflare 경유 접속과 휴대전화 크기의 Edge 화면은 확인했지만 별도 휴대전화의 모바일 데이터망 검사는 사용자가 직접 확인해야 한다. 사용자가 취소한 헤더 색 변경은 적용하지 않았다.

최종 검수 모델은 `gpt-6-astra(high)`였다. 코드·문서 검수에서 옛 작업 시점의 `외부 공개 없음`·`STUDENT_HOURS=false` 안내가 최신 상태처럼 보이는 문서 문제를 발견해 시점을 명시하고 고쳤다. 재검수 결과 **PASS**였다. 공개 주소에서 잠깐 느린 브라우저 응답이 있었으나 `/health`는 계속 200이었고 Edge 화면을 다시 열어 `우주와 연결되었어요` 상태까지 확인했다. 임시 터널에는 가동 시간 보장이 없으므로 계속 사용할 때 연결 상태를 확인한다.
