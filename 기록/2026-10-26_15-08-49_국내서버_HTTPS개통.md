# 국내 서버 설치와 woozooclass.kr 개통

- 작업 도구: Codex, OpenSSH, PowerShell, iwinv 관리 브라우저
- 사용 모델: 본체 세션 기본 모델, 검증 도우미·보강 및 최종 검수 gpt-6-astra

## 1. 요청 요약

교실 프로그램을 새 국내 서버에 설치하고 도메인으로 접속되도록 끝까지 진행한다. 사용자가 필요한 외부 송신 TCP80/443, TCP·UDP53, UDP123을 명시 승인하고 iwinv 홈페이지에 재로그인했다. 기존 교실 이전은 하지 않는다.

## 2. 계획

SSH 키 접속과 빈 서버 확인 → 코드만 전송 → 제한된 송신 허용 → 공식 실행 환경 설치 → 전용 비root 계정·새 비공개 설정 → Caddy HTTPS → 외부/저장/백업 검증.

## 3. 변경 내용·파일

- ELCAP 송신에 승인한 포트 5개만 추가. 인바운드 SSH는 현재 관리 PC, HTTP/HTTPS는 공개하고 3000은 공개하지 않았다. 전체 포트 허용은 하지 않았다.
- Ubuntu24.04.4 x86_64 새 서버에 Node24.22.1, pnpm11.19.0, Caddy2.11.7을 공식 배포처에서 설치. Node는 HTTPS 공식 SHA256 목록과 일치 확인, 패키지는 서명된 apt 저장소 사용.
- Git `11dcfd529842607088b331b983f52d37f4cfa204`의 client/shared/server/scripts/deploy/package/lockfile만 압축 전송했다. 1,247,386,509바이트, 양쪽 SHA256 `27883754bd7f38d4a0f62a0b1ad64b483b1466673eee225bd50f4f8287979638` 일치. 기존 .env/.local/data·개인 키는 제외했다.
- `/opt/woozooclass/releases/11dcfd529842607088b331b983f52d37f4cfa204`와 current 링크, 전용 `woozooclass` 사용자, root0600 설정, 사용자0700 자료, root0700 백업을 생성했다. lockfile 고정·설치 스크립트 무실행으로 운영 의존성만 설치했다.
- systemd 앱·Caddy 부팅 자동 시작, Caddy HTTPS 및 자동 인증서 관리, 매일04:10 KST 로컬 백업 타이머를 활성화했다. 실제 백업은 앱을 잠깐 정상 종료하고 재시작한다. 14일 초과 생성 백업 정리 정책을 사용한다.
- `deploy/check-host.sh`: systemd가 Node listen 전에 active가 되는 경합에 연결 거부 재시도를 추가했다. 최종 curl 실패 시 빈 응답 JSON 파싱을 중단한다. 운영 릴리스의 해당 검사 파일에만 패치를 적용했다(SHA256 `e96cecd18be488c86315cc27a39374bb91c469d22a966bba40cd82a82f6f1b12`). 앱 코드는 위 릴리스 그대로다.

## 4. 검증

- systemd 단위 검증, Caddy 설정 검증 PASS. Let's Encrypt 인증서 발급 성공, 도메인 A가 새 서버를 가리킨다.
- 공개 HTTPS200, HTTP308→HTTPS, 실제 WSS와 Socket.IO namespace 접속 PASS. 3000 외부 연결 시간 초과, 앱3000·Caddy관리2019는 loopback 바인딩이다.
- .env/.local/data/classes/deploy/server 경로404. 실제 IAB 시작 화면·교사 입장/새 교실 입력 화면 확인. 테스트 중 백업으로 잠시 발생한502 이후 새로고침으로 복구 확인했다.
- Windows Node 기본 신뢰 저장소에서 SELF_SIGNED_CERT_IN_CHAIN이 발생했지만 Windows curl·브라우저는 정상이다. Node `--use-system-ca`로 OS 신뢰 저장소를 사용한 HTTPS/WSS 검사는 통과했다. 인증서 검증을 끄거나 경고를 우회하지 않았다. 기관망 인증서 개입 가능성을 추정할 수 있으나 정확한 원인·프로그램은 미확정이다.
- 독립 임시 저장소에서 가상계정 생성→37별파편→정상 종료→같은 ID/PIN/잔액 복원→별도 압축복구 PASS. 최초 검사 제목이12자 제한을 넘어 실패해 제목을 수정했다. 게임의 닉네임 검증은 변경하지 않았다. 운영 학급 JSON은0개이며 실제 학생 계정을 만들지 않았다.
- 실제 backup.service Result=success/ExecMainStatus=0, 백업 SHA256 검증 PASS. 타이머의 다음 실행04:10 KST 확인. 백업 후 앱 active/NRestarts0 및 HTTPS 정상 복귀 확인.
- 검사 시작 경합 보강은 지연 시작·계속 미시작의 회귀2건 및 Bash 문법 PASS. 서버 실제 백업 직후 보강 검사도 PASS.
- 앱 기능 코드 변경 없음. 정원 변경의 기존 전체1,177·기본화면91·정원5와 후속 진화43·화면12 검증 증거를 재사용하고 실제 운영환경 검사를 추가했다. 35명 동시 전투 부하 검사는 하지 않았다.

## 5. 최종 검수

gpt-6-astra가 구성·실행 결과·검증 범위 및 시작 경합 보강을 검수했다. 개통과 운영 학급 생성, 동일 디스크 백업과 외부 재해복구를 구분해서 인계한다.

## 6. 미완료·사용자 다음 단계

- 운영 학급은 비어 있다. `/admin.html`에서 관리자 로그인→교실/선생님 이름 입력→선생님 코드 발급→학생 계정 추가 순으로 시작한다. 학급별 학생 최대35명, 초기 활성 교실 한도1, 학생07~22시다.
- 관리자 비밀번호를 PC 비공개 파일로 내려받는 시도는 민감정보의 명시적 전달 승인이 부족하다는 자동 검토 거부로 실행되지 않았다. 값을 읽거나 출력하지 않았고 별도 사용자 승인을 요청했다. 승인 전 서버에만 보관한다.
- 외부 암호화 백업은 미구성이다. 같은 서버의 로컬 백업은 서버·디스크 자체 소실에 대비할 수 없다. 별도 저장소 선택과 비용/전송 승인이 필요하다.
- 두 번째 관리 PC 키/IP는 미등록. 학생·교사는 SSH 키 없이 웹으로 접속한다. 학교망의 별도 도메인 허용 정책까지 보장할 수는 없다.
- Caddy 뒤 로그인 실패 제한 합산은 기존 보수적 동작을 유지했다. 여러 교실 확대 전 개선이 필요하다. 실제35명 부하 한계는 미실측이다.
- 이전에 채팅에 공유된 서버 로그인 비밀번호는 사용자 직접 변경을 권고한다. 새 비밀번호를 대화·Git에 기록하지 않는다.

## 7. Git

운영 검사 보강·메인·본 기록만 선별 저장한다. 모든 키·비밀번호·백업·검증 임시자료·스크린샷은 제외한다. push 및 실제 원격 SHA는 실행 후 최종 답변에서 확인한다.
