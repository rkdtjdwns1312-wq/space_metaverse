## 4. 핵심 설계 원칙 (지키지 않으면 테스트가 깨진다)

- **서버가 판정한다.** 이동·충돌·거리·소속·권한·잔액·거래는 전부 서버. 화면은 버튼 표시만 조절한다. 교사 권한은 `socket.data.session.player.role==='teacher'`로만.
- **스냅샷은 받는 사람별.** `store.snapshot(room, viewer)`: 학생은 자기 `starShards`/`inventory`만 받고 남의 것은 키 자체가 없다. `effects`의 `fromId`, `itemLog`, `tradeLog`, 남의 `trades`는 교사만. `io.to(room).emit('room:state')`를 쓰면 비밀이 새므로 금지. 반드시 `roster(room)`.
- **안내 두 종류.** `announce(room, text)`는 방 기록에 남는 공개 시스템 채팅. `whisper(room, player, text)`는 그 사람에게만(`private:true`), `player.notes`에 최근 20개 보관되어 재접속 시 함께 온다. 숫자가 드러나는 개인 정보(별 파편 지급, 거래)는 whisper.
- **맵 id.** `'space-plaza'`(광장) / `'star-street'`(별빛 거리) / `'planet:<uuid>'`(행성 내부). 같은 맵에 있는 사람만 서로 보인다(위치는 전원에게 가고 화면이 거른다). `mapOf(mapId, room.planets.values())`로 맵 정의를 얻는다.
- **행성은 방마다 동적 데이터.** `room.planets: Map`, `room.proposals: Map`. id는 UUID. 종류는 `templateId`.
- **설정은 `shared/config.js`에만.** 수치를 코드에 박지 않는다. 화면도 같은 파일을 `import`한다(`/shared` 정적 서빙).
- **화면 보안.** CSP `style-src 'self'`라 인라인 `style="…"` 속성 금지(JS로 `el.style.x=`는 됨). 사용자 텍스트는 `textContent`/`fillText`만, `innerHTML` 금지.
- **한국어 조사.** 이름·아이템명이 동적이므로 `ro()`('로/으로'), `eul()`('을/를'), `iga()`('이/가')를 쓴다.

## 5. 소켓 프로토콜 요약

모든 요청은 `socket.emitWithAck(event, data)` → `{ok:true, ...결과}` 또는 `{ok:false, error:'한국어 문구'}`.

| 영역 | 이벤트 | 비고 |
| --- | --- | --- |
| 입장 | `room:create {teacherKey,title,allowedNames,seedPlanets}`, `room:join {code,nickname}`, `session:resume {token}`, `room:leave`, `room:close`(교사) | 입장 결과 `{token, selfId, room(스냅샷), chat:{messages}}`. 토큰은 `sessionStorage`. 교사 종료 시 방 파괴 |
| 이동 | `player:input {x,y}`(ack 없음, volatile) → `world:positions {positions:[[id,x,y]]}` | 서버 tick 이동 |
| 채팅 | `chat:send {text}`, 교사 `chat:setEnabled`, `chat:mute {playerId,muted}`, `chat:clear` → `chat:message`, `chat:cleared` | 필터·쿨다운 700ms·120자 |
| 행성 | `planet:propose/create {templateId,name,description,x,y,color}`, `planet:approve/reject/withdraw {proposalId}`, `planet:remove`, `planet:join/leave/enter {planetId}`, `planet:exit`, `planet:rules:set {planetId,rules[]}`, `planet:rename:propose/vote/set` | 학생 신청 → 교사 승인. 입장은 광장·소속(교사 예외)·거리 검사. 이름은 소속 과반 투표 |
| 맵 | `map:travel {to}` | 현재 맵의 문(gate) 가까이에서만 |
| 별 파편·상점 | 교사 `shards:give {playerId|'all', amount}`, `shop:buy/sell {itemId,quantity}` | 상점은 별빛 거리 별상점 근접. 판매가 절반 |
| 아이템 | `item:use {itemId,targetId}` → `{inventory, effects}` | 레벨·대상·쿨다운 2초·효과 3개 |
| 거래 | `trade:propose {targetId,give,want}`, `trade:respond {tradeId,accept}`, `trade:cancel`, 교사 `trade:approve/reject` | 승인 시에만 교환(원자적). 거절 후 같은 상대 5분 차단 |
| 상태 | `room:state`(개인 스냅샷), `room:closed` | 스냅샷 필드: `code,title,mapId,maxPlayers,chat.enabled,planets[],proposals[],players[](id,nickname,role,x,y,connected,avatar,muted,mapId,departmentId,effects[],starShards?,inventory?),trades[],itemLog?,tradeLog?` |

정확한 문구와 검사 순서는 `server/app.js`와 `tests/realtime.test.js`가 기준이다.

## 7. 다음 작업: 요청 027 지속 저장 (1년 단위 유지) — 설계 제안

사용자 요구: "지금은 매번 교실 코드가 바뀌고 초기화되는데, 아이들이 만든 것들과 코드가 최소 1년 단위로 지속되어야 한다(교육과정 1년)." 현재는 전부 메모리라 서버를 끄면 사라지고 교사 연결이 끊긴 채 60초가 지나면 방이 파괴된다.

권장 설계(변경 가능, 결정 사항은 사용자에게 짧게 확인):

1. **교실(class)과 수업(session)을 분리.** 교실은 코드가 고정된 영구 데이터, 수업은 서버가 켜져 있는 동안의 실시간 상태. 교사가 '교실 열기'(코드 + 교사 키)를 하면 저장된 교실을 불러와 방을 만든다. 처음 만들 때만 새 코드. `교실 만들기` 폼에 '기존 교실 열기' 탭 추가.
2. **저장 대상**: code, title, allowedNames, createdAt, planets(규칙·소속·templateId 포함), proposals, chat.history(최근 50), itemLog/tradeLog, 학생별 영구 데이터(닉네임 기준: starShards, inventory, avatar(level·xp·departmentId), notes, pin 해시). 저장하지 않는 것: 위치·mapId·세션 토큰·연결 상태·진행 중 거래(끝내지 않은 거래는 취소).
3. **저장소**: 로컬 JSON 파일 `data/classes/<code>.json`(`data/`는 gitignore). 변경이 있을 때 디바운스(예: 1초)로 원자적 저장(임시 파일 후 rename). 서버 시작 시 `data/classes/*.json`을 읽어 '닫힌 교실' 목록으로 보관. 배포(Render Free)에서는 디스크가 사라지므로 외부 저장소(무료 Turso/Supabase 등)가 필요 — 배포 단계에서 결정.
4. **학생 본인 확인**: 요구사항 012에 "닉네임 단독을 인증으로 쓰지 않는다"가 있다. 첫 입장 때 학생이 4자리 번호(PIN)를 정하고(`scrypt` 해시 저장), 이후 입장 시 코드+닉네임+PIN. 교사는 선생님 도구에서 PIN 초기화. 틀린 PIN 5회면 1분 잠금.
5. **수업 마치기**: 교사의 '교실 종료하기'를 '수업 마치기'로 바꿔 저장 후 방을 닫되 코드는 유지. 교사 연결이 60초 끊겨도 방을 파괴하지 않고 '일시 정지'(학생 이동 정지, 저장 유지)로. 진짜 삭제는 선생님 도구의 '교실 완전히 지우기'(확인 2회).
6. **구현 순서 제안**: (a) `server/store.js` 파일 저장 계층(load/save/list) + 단위 테스트 → (b) `RoomStore`에 직렬화/복원(`toRecord`/`fromRecord`) → (c) `room:open`(교사, 코드+키) 액션과 폼 → (d) 학생 PIN → (e) 수업 마치기·일시 정지 → (f) `verify-browser.mjs`에 "서버 재시작 후 같은 코드로 열기 → 행성·잔액·가방 유지" 시나리오(스크립트가 `createClassroomServer`를 직접 띄우므로 close 후 다시 listen하면 된다) → (g) README 갱신.
7. **주의**: `RoomStore.sessions`(재접속 토큰)와 `players`의 `socketId`는 복원하지 않는다. 복원 시 각 학생은 '연결 안 됨' 상태로 두고 입장할 때 채운다. 스냅샷 크기·비밀 규칙은 그대로.

그 다음: STEP 8 교사 관리 나머지(강제 퇴장, 이동 잠금, 지정 위치/선생님 앞으로 모으기, 개별·전체 아이템 지급) → 아이템 효과 그림(helmet·cape·trail·orbit·speed는 아직 아이콘만) → 레벨·경험치·능력·과제 탭 채우기 → 행성 일러스트 첨부(요청 025, `PLANET_TEMPLATES[].image` 자리) → Render 배포.

## 8. 설계 판단이 필요한 것 (사용자에게 짧게 확인)

## 9. 함정과 주의 (실제로 겪은 것)

- `verify-browser.mjs`는 셀렉터·문구에 강하게 묶여 있다. 화면 문구·id·대화상자 구조를 바꾸면 스크립트도 같이 고쳐야 한다. `#players`·`button.mute`는 `#crew-dialog` 안, `#proposals`·거래 승인·기록은 `#teacher-dialog` 안(먼저 `#crew-button`/`#teacher-tools` 클릭). `#bag-list li`는 보유 종류 수(빈 칸은 `div`).
- `holdKey` 고정 시간은 속도 310 기준. `RULES.speed`를 바꾸면 재조정.
- 좁은 화면에서 캔버스가 `object-fit:contain`으로 레터박스가 생긴다. 클릭 좌표는 `canvasPoint()`가 보정하므로 캔버스 CSS를 바꿀 때 그 함수를 함께 본다.
- 행성 배치 예약 구역(`PLANET.reserved`, 왼쪽 아래 이동 버튼 자리)과 별·문·기존 행성 간격 30px. 예시 청소행성(190,565)이 예약 구역과 겹치지 않도록 y 640부터로 잡았다.
- 새 행성은 종류별 기본 규칙(대개 3줄)로 시작한다. 규칙 편집 검사에서 저장 후 개수가 바뀔 때까지 기다려야 한다(경합).
- 서브에이전트가 `CLAUDE.md`를 읽고 파이프라인을 재귀 적용해 시간을 낭비한 적이 있다. Codex도 하위 에이전트에 규칙 파일 전체 대신 필요한 범위만 전달한다.
- PowerShell 5.1: `&&` 없음, 네이티브 명령에 `2>&1` 금지, `Set-Content`는 ANSI라 파일은 도구/UTF-8로만 쓴다. 커밋 메시지는 파일로 저장해 `-F`로 전달.
- 서버 실행 중 파일을 바꾸면 `교실-시작.cmd` 창을 닫고 다시 켜야 반영된다(`pnpm dev`는 자동 재시작).
- `.local/teacher.html`에는 교사 키가 들어 있다. 화면 공유·기록에 노출 금지.

## 10. 작업 절차 (Codex 기준, `메인.md` 협업 규칙과 동일)

1. `git pull --ff-only origin main` → `메인.md`·이 문서 읽기 → 요청 이력에 다음 번호(033)로 '진행 중' 추가.

4. 검수(AGENTS.md 규칙) → commit → `git push origin main` → 로컬 HEAD=origin/main 확인 → 작업 트리 깨끗하게.
