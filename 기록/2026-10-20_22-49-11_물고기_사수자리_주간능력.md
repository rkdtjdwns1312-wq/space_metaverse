# 물고기·사수자리 주간 능력 Lv2~5

- 작업 도구: Codex desktop / PowerShell / Node.js 24.
- 구현: Codex. 최종 읽기 전용 검수는 gpt-6-astra로 지정해 둔 기존 에이전트를 재사용했다. 응답에는 GPT-6 기반 Codex로 표시되며 세부 모델 ID는 응답 자체에 노출되지 않았다.
- 한국 시간: 2026-10-20.

## 1. 요청 요약

물고기자리는 수락 가능한 1/2/3/5일 짝을 만들고, Lv3/4는 상대가 받는 경고를 신청자도 받는다. 사수자리는 단계별로 자기 경고 또는 자기 검은별을 해제한다. 사용자 확인에 따라 경고·검은별 해제 대상은 **자신만**이다.

## 2. 계획과 결정

물고기 짝은 상대가 수락할 때 주간 사용권을 소모한다. 수락 뒤에는 두 학생을 해제할 수 없는 2인 파티로 묶어 보상을 공유하고, 기간이 끝나면 자동 해제한다. 거절 시 5분 동안 같은 친구에게 재신청할 수 없다. 게임 내 짝 상태와 종료 시각은 교사 도구에 표시하며 실제 책상·급식 자리 배치는 교사가 맡는다. 사수 Lv2/3은 자기 부서 경고 한 건을 각각 주 1/2회, Lv4는 자기 검은별을 주 1회, Lv5는 자기 검은별 주 2회 또는 한 부서의 자기 경고 전부 주 1회를 선택한다. Lv5의 두 방식은 같은 주에 섞어 쓰지 않는다. 검은별 해제 때는 해당 상태의 원인 부서 경고를 지우고 다른 부서의 자기 경고는 남긴다.

## 3. 변경 내용과 파일

`shared/constellation-weekly-abilities.js`, `shared/constellation-abilities.js`, `shared/constellation-stages.js`에 단계별 규칙·설명을 등록했다. `server/party.js`, `server/persistent-rooms.js`, `server/rooms.js`, `server/app.js`에 짝 신청·수락/거절·만료·재시작 복원과 잠금 파티·교사 확인 경로를 연결했다. `server/warnings.js`, `server/constellation-weekly-abilities.js`에는 Lv3/4 경고 공유와 사수의 자기 대상 삭제·주간 횟수·방식 선검증을 구현했다. `client/party-ui.js`, `client/constellation-ability-ui.js`, `client/app.js`, `client/style.css`에는 신청/선택/파티·교사 표시를 연결했다. 관련 서버 검사 2개와 주간 능력 브라우저 흐름을 추가했다.

## 4. 검증

관련 물고기·사수 서버 검사 19/19 통과. 최종 전체 서버 검사 `node --test --test-concurrency=1 tests/*.test.js` **1,080/1,080 통과**. 기본 브라우저 검사 85개 흐름·오류 0, 주간 능력 실제 브라우저 검사 16개 흐름·오류 0: 물고기 신청 거절·재신청·수락·파티 잠금, 사수 자기 경고 선택·삭제, 390px 창 너비 확인. `node --check`, `git diff --check` 통과. 첫 전체 검사는 로컬 소켓이 샌드박스에 막혀 중단했고, 승인된 로컬 소켓 검사에서 천칭자리 기존 검사 1건이 실패했다. 해당 검사는 단독 10회 모두 통과했으며 화면 검사를 동시에 실행하지 않은 최종 전체 검사에서 1,080건 모두 통과했다.

## 5. 최종 검수

Astra 첫 검수에서 사수 Lv5 방식 전환 시 비영속 방의 삭제 순서와 물고기 신청 거절 뒤 버튼 갱신 2건을 발견했다. 사수는 삭제 전에 방식·횟수를 검사하고, 물고기는 초대·거절 상태를 화면 갱신 기준에 포함했다. 회귀 검사를 추가한 뒤 같은 검수 에이전트가 두 수정 모두 PASS, 남은 중대한 문제 없음으로 재확인했다.

## 6. 미완료 및 다음 작업

나머지 7종 별자리의 주간 능력은 사용자가 정하는 대로 구현한다. 실제 교실 책상·급식 자리는 게임이 자동 배치할 수 없어 선생님 도구의 짝 명단을 보고 교사가 함께 앉도록 정해야 한다. 이 PC의 학급 저장 파일 1개를 비공개 `.local`에 백업하고 SHA-256 일치 확인 후 기존 프로세스를 검증해 새 로컬 서버로 재시작했다. `/health`는 `ok=true`, `persistent=true`로 응답했다. 외부 공개는 이번 작업 범위가 아니다.

## 7. Git

이번 작업 파일만 선별해 커밋·`origin/main`에 push하고 실제 원격 SHA를 확인할 예정이다. 기존 사용자의 HWP 삭제 상태와 미추적 몬스터 디자인은 손대지 않는다. `.env`·`.local`·`data/classes`와 학생 정보·비밀 코드는 Git에 넣지 않는다.
