## 3. 수행 내용과 변경 파일

- 실제 로컬 3000번 서버 연결 거부. 저장 잠금 소유 PID18744는 `process.kill(pid,0)` 결과 **ESRCH(없음)**. `node scripts/local.mjs`에서 `.writer.lock` EEXIST 재현. 서버 종료 뒤 남은 잠금을 수동 복구해야만 하는 실행 흐름이 재시작을 막았다.
- 이전 서버 종료 자체의 원인(컴퓨터 종료·프로세스 종료 등)은 로그로 확인되지 않았다. 정확한 종료 원인을 단정하지 않았다.
- `scripts/local-state.mjs`: 먼저 기존 교실 `/health` 응답 검사. 확인된 기존 서버는 재사용. 응답이 다른 서비스이거나 불명확하면 중단. 새 서버를 켜기 전 기존 `unlockStoppedStore`를 사용해 **실제 종료 확인된 PID의 잠금만** 복구. 실행 중이거나 손상된 잠금은 보존. listen 실패 시 새 저장소 정리.
- `scripts/local.mjs`: 위 흐름 연결, 읽기 쉬운 오류, 중복 실행 시 기존 교사 화면 열기. 기존 로컬 전용 서버에 외부 실행 요청 시 기존 서버를 Ctrl+C 종료하고 다시 외부 실행하도록 안내. 함부로 프로세스를 죽이지 않는다. 교사용 시작 파일은 로컬 주소에만 사용한다.
- `server/app.js`: health에 앱 식별 `service`와 현재 `publicOrigin`을 추가하여 실행기가 교실과 외부 연결 모드를 확인한다. 비밀번호·학생 정보는 추가하지 않았다.
- 두 시작 CMD의 안내를 새 서버 창 유지 안내로 정리했다. 두 파일 모두 CRLF 유지.
- `tests/local-start.test.js`: 최초/중복 시작, 죽은 소유자 잠금 복구와 파일 보존, 살아 있는 소유자/손상 잠금 보호, 다른 HTTP 서버 거부.
- README의 실행·종료·외부 접속·잠금 복구 안내 갱신. 초보자 안내에 불필요한 내부 프로토콜 설명은 본체 검수에서 줄였다.
