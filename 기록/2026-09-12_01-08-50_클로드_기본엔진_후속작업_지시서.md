## 현재까지 만들어진 것

- Node.js 22 이상, Express, Socket.IO 기반의 한 서버 구조
- `shared/config.js`: 30명 제한, 맵 크기, 이동 속도, LV1 소행성 및 향후 레벨·별자리·장비 데이터 계약
- `server/rooms.js`: 교실 코드 생성, 교사 비밀키를 서버에서 검사하는 방 생성, 허용 닉네임 확인, 학생 방 입장, 총 30명 제한, 60초 재접속 세션, 서버에서만 관리하는 학생 상태
- `server/world.js`: 서버 기준 이동, 맵 경계, 행성·별과의 충돌, 학생 소행성 겹침 방지
- `server/app.js`: 방별 Socket.IO 통신, 서버 권한 검사, 교사 연결 종료 시 교실 종료, 잘못된 입력 제한, 기본 보안 헤더
- `client/`: 한국어 파스텔톤 우주 광장, 교사·학생 입장 화면, LV1 작은 소행성, 닉네임, 친구 목록, 키보드 WASD/방향키와 화면 터치 이동
- `scripts/local.mjs`, `교실-시작.cmd`, `.env.example`, `render.yaml`: 로컬 실행과 향후 Render Free 배포 준비
- 채팅·오브젝트 상호작용·아이템·교사 관리 패널은 아직 구현하지 않음. 이번 위임에서 앞 단계 확인 전에 추가하지 않습니다.

- 검증 과정에서 로컬 서버가 남아 있을 수 있으므로 작업 시작 시 해당 프로세스를 확인합니다. 사용 중인 서버를 함부로 종료하지 말고, 직접 시작한 테스트 서버라면 검증 후 정리합니다.

## 반드시 끝낼 작업

### 1. STEP 3~4를 완성

- 브라우저 검증 오류의 원인을 수정합니다.
- `node --test tests/*.test.js`와 `node scripts/verify-browser.mjs`를 다시 실행합니다.
- 교사 창에서 방을 만들고 방 코드가 보이는지, 학생 창에서 허용된 번호로 입장하는지, 허용되지 않은 이름이 거절되는지 확인합니다.
- 교사와 학생이 같은 맵에서 서로 보이고 움직임이 동기화되는지 확인합니다.
- 서로 다른 방 참가자가 보이지 않는지, 경계·행성·소행성 충돌이 작동하는지 확인합니다.
- 새로고침 뒤 같은 학생 소행성으로 돌아오는지, 교사 종료 뒤 학생 화면이 입장 화면으로 돌아오는지 확인합니다.
- 가로 390px 정도의 화면에서 터치 이동 버튼이 보이고 가로 스크롤이 생기지 않는지 확인합니다.
- 캡처한 화면은 `.local/` 아래에 두며 비밀키·세션 토큰을 저장소에 남기지 않습니다.

### 2. 초보자용 README 작성

`README.md`를 한국어로 작성합니다. 다음 내용을 실제 파일과 명령어에 맞게 설명합니다.

- 이 프로젝트가 무엇인지
- 필요한 것: Node.js 22 이상
- 처음 한 번 준비: `pnpm install`
- 가장 쉬운 실행: `교실-시작.cmd` 더블클릭
- 교사 화면에서 방 만들기 → 표시된 코드를 학생에게 알려주기 → 학생은 같은 주소에서 코드와 허용된 번호 입력
- 교사 창과 학생 창 두 개로 이동을 확인하는 방법
- 종료 방법
- 현재 구현 범위와 아직 구현하지 않은 채팅·아이템·관리 기능
- `TEACHER_KEY`가 무엇인지와 학생에게 공유하지 않는다는 설명
- Render 무료 테스트는 별도 단계이며 아직 배포하지 않았다는 설명. Free 서버는 정지·재시작으로 메모리 상태가 사라질 수 있으므로 실제 수업 운영용으로 바로 단정하지 않음.
- 이후 채팅 → 오브젝트 → 아이템 → 교사 관리 순서

명령어를 사용자에게 실행시키기 전에 가능한 것은 작업자가 직접 실행하고, README는 따라 하기 쉬운 순서로 씁니다. `pnpm-lock.yaml`과 실제 설치 버전을 보존합니다.
