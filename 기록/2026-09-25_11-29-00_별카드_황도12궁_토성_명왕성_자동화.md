## 2 계획

## 3 수행 내용과 변경 파일

- shared/star-card-automation.js: 신규3종 자동 안내, 수량별 할인 산식. 원본 PPT/30종 원문은 변경하지 않았다.
- server/star-cards.js: 선택·할인·사용 제한, 엄격한 버전 검증. 버전 없는 기존 record는 이전 automatic/manual/status 그대로 읽으며 새 효과 대상이 아니다.
- 황도12궁: 본인 학생만 한 번 선택. LV1은 XP, LV2~5는 현재16종 중 다른 별자리 또는 XP. 별자리 최대2명 제한만 예외이고 레벨/경험치/계열 능력 사용 기록을 보존한다. XP는 서버 주사위1~6×3 cap10, 단계초과분 파편환산. 파편 공간은 추첨 전에 최대 초과량으로 검사하여 실패를 이용한 주사위 재추첨을 막는다. 미선택 카드는 재접속 후 신전 F로 다시 선택한다.
- 토성: 카드별·물품 종류별1개 할인, 여러 장은 구매 개수별로 배분하며 물품 한 개에 중첩하지 않는다. 수량이 할인 횟수보다 많으면 초과 물품 정가. 가격1→0, 실패 구매는 기회 보존. 할인 소진 항목은 기록에 저장하지만 publicRecord에서 제거한다. server/rooms.js는 본인 shopDiscounts만 별도 전달한다.
- 명왕성: 같은 방의 다른 학생 새 item:use(LV1/LV2/별카드)·draw:start를 한국 자정까지 차단한다. 사용자가 나가도 지속한다. 교사 사용·관리, 이미 소비한 달토끼 draw:pick은 허용. 교사 종료 시 즉시 해제. 현실 자리 지정은 교사 확인으로 남긴다.
- server/app.js: 기존 저장 트랜잭션으로 신규 API star-card:choose 연결, 상점 할인 소진/결과, 각 아이템 시작 경로 제한. 클라이언트가 소유자·가격·주사위·보상을 정하지 않는다.
- client/star-card-ui.js/css·index.html: 선택→확정/취소, 4×4, LV1 변경불가, 중복 입력 방지, 화면 갱신 중 선택 보존. CSS는 바닐라 앱의 link 방식으로 로드한다.
- client/app.js: 실제 구매수량 총액·토성 할인 개수 표시, 구매 후 수량 유지·가격 갱신, 잔액 부족 시 버튼 비활성화. scripts/verify-browser.mjs의 기존 ‘부족해도 클릭’ 검사는 새 UI에 맞게 비활성/가격/잔액·가방 무변경을 검사한다. 서버의 부족금액 거부는 소켓 검사로 별도 유지한다.
- README: 사용자 버튼 순서·원자 저장·신규 적용과 남은 수동 카드 구분. 신규 단위/소켓/브라우저 검사 파일 추가.

## 7 Git 동기화 결과

시작 pull은 샌드박스 FETCH_HEAD 쓰기 거부 후, 기존 사용자 승인에 따라 권한 상승으로 재시도하여 Already up to date 확인. 변경 파일만 선별하여 commit/push하고 실제 원격 main과 비교한다. 사용자 미추적 `몬스터 디자인/`는 그대로 남기므로 전체 작업 트리를 clean이라고 보고하지 않는다. 최종 커밋·운영 확인은 메인.md 최신 요청196 항목을 따른다.

구현 커밋 **500e5b4**를 origin/main에 push 완료. 로컬 HEAD·origin/main·git ls-remote의 실제 GitHub main 일치 확인. 추적 파일 수정 없음, 기존 `몬스터 디자인/`만 미추적 보존. 이 완료 확인을 담은 문서 보완 커밋도 push한다. 강제 push 없음, 실제 학급·비밀 조합·교사키 포함 없음.
