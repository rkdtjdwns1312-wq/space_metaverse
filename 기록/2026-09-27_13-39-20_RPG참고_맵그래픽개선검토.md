# 요청250 · RPG 참고 맵 그래픽 개선 가능 여부

- 작업 도구: Codex
- 사용 모델·검수 모델: gpt-6-astra(Astra), 본체 직접 검토

## 1. 요청 요약

트릭스터·테일즈위버의 맵 모양과 그래픽을 학습/참고하여 현재 우주교실 맵을 개선할 수 있는지 설명. 지금 변경하지 않기.

## 2. 계획

공식 참고 자료와 현행 렌더링 구조를 확인하고 가능한 표현·구현 범위와 후속 제작 순서를 안내한다. 모델 재학습을 완료했다거나 게임 전체를 분석했다고 주장하지 않는다.

## 3. 수행 내용과 변경 파일

게임 변경 없음. `client/scenery.js`, `client/world.js`, `shared/paradise-floor.js` 읽기: Canvas 배경 캐시·이미지 렌더·별도 이동 바닥·아바타끼리 y정렬 확인. 맵을 배경/바닥/소품/전경으로 분리하고 소품과 캐릭터의 공통 앞뒤 정렬을 추가하는 방식 제안. 원형 플랫폼을 광장·정원·계단·다리·자연스러운 지형으로 재구성할 수 있으나 그림에 맞는 서버 이동경계와 상호작용/미니맵도 함께 조정해야 한다.

배경 원화를 참고해 시점·색·질감·공간 배치를 분석하는 작업이며, 원작 자산 추출이나 AI 모델 재훈련은 실시하지 않는다. 현재 캐릭터는 부드러운 일러스트 계열이므로 우주/파스텔 동화풍 배경과 조화를 우선하고 엄격한 도트화는 별도 선택으로 둔다. 이미지 생성은 이번에 하지 않음.

## 4. 검증 결과

Git pull --ff-only: 이미 최신(6b999d6). 현행 코드의 배경/이동구역 분리 확인. 문서만 변경하여 실행 테스트 불필요, 운영 서버/데이터 그대로. 공식 참고: [테일즈위버 가이드](https://static.tales.nexon.com/GameGuide/Guide), [NC의 트릭스터M 개발진 인터뷰](https://about.ncsoft.com/news/article/nc-play-20201110-tm). 후자는 원작과 모바일 후속작을 구분하며 원작 전체 맵 자료를 수집한 것으로 표현하지 않는다.

## 5. 최종 점검(검수)

Astra 직접 검수. 가능성 안내와 실제 구현 완료를 구분. 시안 한 장만으로 상용 게임 수준을 보장하지 않고 그림 정리·충돌·가림·성능 검사가 필요함을 설명한다. 짧은 읽기/설명 작업으로 본체 처리.

## 6. 미완료 사항과 다음 단계

사용자가 추후 제작을 요청하면 선호하는 원작 장면 몇 개를 기준으로 디자인 기준 정리 → 별의 기원 시안 → 별도 시험 맵 → 사용자 확인 후 확대. 학생 이동·채팅·아이템·계정은 기존 엔진을 활용. 크롬북 실기 성능은 실제 새 그림 적용 후 확인해야 한다. 이번에는 변경 요청하지 않았으므로 시안 생성도 보류.

## 7. Git 동기화 결과

요청 이력과 이 기록 두 문서만 commit/push 후 실제 원격 main을 확인한다. 사용자 미추적 원본 `몬스터 디자인/`은 보존한다. 게임 코드와 이미지 변경 없음.
