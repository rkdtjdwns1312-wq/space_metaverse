# Lv4 장비와 능력치 표시 순서

- 작업 도구: Codex · PowerShell · Node.js
- 사용 모델: GPT-6 기반 Codex
- 최종 검수: `gpt-6-astra` 지정 에이전트 요청 · PASS. 실제 런타임의 정확한 Astra 변형 여부는 확인 불가.

## 1. 요청 요약

Lv4 별빛 수호석에 방어력+1·체력+20·10초마다 체력 회복+1을 적용한다. 따뜻한 반지→따뜻한 해의 반지, 달의 귀걸이→차가운 달의 귀걸이로 변경하며 다른 효과는 유지한다. 모든 장비 능력치의 표시 순서를 통일한다.

## 2. 계획

기존 장비 ID·조합법을 보존하고 장비 정의를 수정한다. 상점·교사 장비 목록·가방이 같은 공유 표시 함수를 쓰도록 연결한다.

## 3. 변경 내용·파일

- `shared/equipment.js`: 별빛 수호석 체력 회복+1, 두 장비 이름 변경. 표시 순서를 공격력→방어력→최대 체력→최대 마나→체력/마나 회복→회복 비율→이동속도→스킬 피해·지속시간→쿨타임으로 고정하는 `equipmentStatText` 추가.
- `client/app.js`, `client/energy-shop-ui.js`: 가방·상점·교사용 전체 장비 목록의 능력치 설명에 같은 함수를 사용.
- `tests/equipment.test.js`, `tests/passive-recovery.test.js`: 이름·수치·표시 순서·10초 회복 검사.

## 4. 검증

- 관련 장비·조합·회복 검사 34/34 PASS, 최종 테스트 추가 후 장비 10/10 PASS.
- 두 클라이언트 파일과 공유 모듈 구문 검사, `git diff --check` PASS.
- 격리 브라우저 실제 화면 확인은 로컬 페이지 탐색 시간 초과로 완료하지 못했다. 첫 시도는 잘못된 import 경로, 후속 시도는 로컬 탐색 자체 시간 초과였다. 자동 검사는 공통 표시 함수 결과와 실제 회복 계산을 확인했다.

## 5. 최종 검수

지정 검수 에이전트가 코드 diff와 테스트 결과를 검토하고 PASS 판정. 검수 에이전트는 GPT-6 기반 Codex라고 보고했으며 Astra 변형 여부는 확인할 수 없었다.

## 6. 미완료·다음

Lv5 장비 수치는 사용자 후속 지시 대기. 운영 홈페이지 미배포. 브라우저 렌더링 확인은 로컬 브라우저 연결이 가능한 환경에서 다시 할 수 있다.
