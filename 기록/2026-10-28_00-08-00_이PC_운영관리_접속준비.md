# 이 PC에서 운영 사이트 관리 접속 준비

- 작업 도구: Codex
- 작업 모델: gpt-6
- 최종 검수 모델: gpt-6-astra(high)

## 1. 요청 요약
이 PC에서도 woozooclass.kr에 관리자 로그인해 기존 PC와 두 곳에서 관리하고 관리자 코드를 확인할 수 있게 하며 GitHub 상태를 확인한다.

## 2. 계획
GitHub 최신 상태와 운영/로컬 자격 증명 분리를 확인한 뒤, 비밀값을 복제하지 않고 관리 화면 접근을 마련한다.

## 3. 변경 내용·파일
`운영교실-관리.url`을 추가해 운영 관리자 페이지로 바로 이동한다. README에 로컬 `.env`와 운영 `app.env`의 비밀번호가 별개이며 GitHub push가 자동 배포는 아니라는 점을 명시했다. 이 PC에서 `.local/woozooclass-admin-access.txt`와 `~/.ssh`가 없음을 확인했다. 이전 PC의 비밀값·학생 자료는 이동하거나 출력하지 않았다.
서버의 `admin:login`은 공통 운영 비밀번호를 각 소켓 연결에서 검증하고 별도 PC 등록을 요구하지 않는다. 두 PC가 각각 동시에 관리자 로그인할 수 있다.

## 4. 검증
GitHub `main`을 ff-only 동기화했고 원격 릴리스 기록을 확인했다. 공개 `https://woozooclass.kr/health`와 `/admin.html`에 이 PC에서 각각 HTTP 200으로 접속했다. 바로가기 URL 내용과 문서 diff를 점검했다. 관리자 로그인과 SSH 배포는 자격 증명이 없어 수행하지 않았다.

## 5. 최종 검수
gpt-6-astra(high) 최종 검수 PASS. 비밀값 노출이 없고 공개 HTTP 200과 실제 관리자 로그인·배포 권한을 구분했으며, GitHub 저장과 운영 배포 경계를 확인했다. 사용자 추가 설명에 따른 두 PC 동시 로그인 문구는 서버 `admin:login` 구현과 대조해 본체가 확인했다.

## 6. 미완료·다음
운영 관리자 비밀번호는 GitHub가 아닌 기존 PC의 `.local/woozooclass-admin-access.txt` 또는 iwinv 비공개 서버 설정에 있다. 이 PC에서 운영 관리자로 실제 로그인하려면 비밀번호를 안전하게 가져와야 한다. 서버 배포 권한을 추가하려면 이 PC의 새 SSH 공개키와 접속 IP를 서버에 등록해야 한다. 등록 전에는 GitHub 코드 관리와 공개 관리자 화면 열기까지만 가능하다.

## 7. Git
기존 사용자 HWP 삭제·미추적 디자인 폴더는 보존한다. 이번 문서·바로가기·기록만 테스트 브랜치에 선별 커밋하고 원격 SHA를 확인한다. 운영 서버 배포는 하지 않는다.
