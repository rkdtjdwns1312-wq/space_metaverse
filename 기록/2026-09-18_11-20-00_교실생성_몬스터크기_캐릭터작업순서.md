# 교실 생성·몬스터 크기와 별자리 캐릭터 작업 순서

- 작업 도구: Codex
- 사용 모델: GPT-5 계열 본체, gpt-5.6-luna/low(요청 103의 범위가 분명한 몬스터 크기 작업)
- 최종 검수 모델: gpt-6-astra/high (Astra)
- 작업 시각: 2026-09-18 11:20 KST

## 1. 요청 요약

- 요청 102: 시작 화면에서 기존 교실 입장과 새 교실 만들기를 분리한다. 새 교실 생성 시 학생 수와 학생별 이름·비밀번호를 줄마다 입력해 계정도 함께 만들고, 선생님 도구에 계정 추가 버튼을 둔다.
- 요청 103: 별의 시작점에서 2단계 몬스터는 1단계의 약 2배, 3단계는 2단계의 약 4배 크기로 만든다.
- 요청 104: 여러 별자리 캐릭터, 진화 그림, Lv1~4 아이템 디자인·기능을 등록할 작업 순서를 제안한다. 이 요청 자체는 순서 문의이며 디자인 파일 등록 지시는 아니다.

## 2. 계획

기존 교실·계정 저장 규칙을 유지하면서 교실 생성 요청에 학생 계정을 원자적으로 포함한다. UI와 저장·재시작 검사를 수행한다. 몬스터 크기는 반지름 1:2:8로 맞추고 겹침·그림 위치를 확인한다. 캐릭터·아이템은 현재 데이터 구조를 조사한 뒤 실제 제작에 앞선 순서를 안내한다.

## 3. 수행 내용과 변경 파일

- `client/index.html`, `client/app.js`, `client/style.css`: 교실 방식 버튼을 분리하고 새 교실에서 학생 수 1~29명에 맞는 이름·4자리 숫자 비밀번호 행을 만든다. 학생 수를 12→13처럼 한 글자씩 바꿔도 다른 행의 입력을 보존한다. 생성 성공·교실 나가기 뒤에는 이 화면의 비밀번호와 숨긴 초안 비밀번호를 비운다. 실패 시 재입력을 피하도록 보존한다.
- `server/persistent-rooms.js`: `studentAccounts`를 검증해 교실과 계정을 함께 만든다. 기존 자동 PIN 생성 방식도 구버전 클라이언트 호환용으로 남긴다. `server/app.js`의 기존 생성 트랜잭션과 실패 시 롤백을 사용한다. PIN 원문은 서버의 영구 기록에 저장하지 않는다.
- `client/accounts-ui.js`, `client/index.html`: 선생님 도구에 ‘아이들 계정 추가하기’ 버튼을 두고 새 학생 계정 입력으로 이동한다.
- `server/monsters.js`, `client/world.js`: 몬스터 반지름을 1단계 24, 2단계 48, 3단계 192로 한다. 큰 몬스터를 겹치지 않게 배치하고 크기에 맞게 충돌·이름표를 조정한다.
- `tests/accounts.test.js`, `tests/monsters.test.js`, `scripts/class-setup.mjs`와 브라우저 검증 스크립트: 새 교실 생성, PIN 적용·재시작 보존, 실패 롤백, 몬스터 크기·겹침, 여러 UI 흐름을 검증하도록 보완했다. `README.md`에 새 사용법을 반영했다.
- 요청 104의 현재 구조: `shared/constellations.js`에 별자리 16종이 등록되어 있다. `shared/config.js`의 아바타는 Lv1 소행성, Lv2부터 별자리, Lv3~5 진화, Lv6 초월체 구조다. 현재 그림은 `client/world.js`의 도형·기호이다. 상점은 `shared/config.js`에 Lv1~3 총 8종이 있고 Lv4 아이템은 아직 없다. 기존 아이템의 효과는 주로 외형 표시이며 이동·전투 능력은 변경하지 않는다.
- 요청 104의 권장 순서: (1) 별자리·진화 단계별 그림 목록과 규격을 정한다. (2) 한 캐릭터의 기본형과 진화형을 먼저 넣어 맵·프로필·모바일 화면에서 시험한다. (3) Lv1~4 아이템을 각각 하나씩 골라 그림뿐 아니라 사용 레벨, 구매 가격, 사용 대상, 지속 시간, 효과가 외형인지 실제 기능인지 정의한다. (4) 그 한 묶음의 상점·가방·착용/사용·서버 검증·저장을 완성한 뒤 나머지 종류로 확장한다.

## 5. 최종 점검(검수)

Astra/high가 처음에 학생 수 순차 입력 시 값 손실과 생성 뒤 PIN 잔존 두 건을 발견했다. 수정 후 Edge 임시 서버에서 순차 입력의 모든 이름·PIN 유지와 생성 성공 뒤 보이는/숨은 PIN 제거를 재현 검증했고, 요청 102·103 코드에 남은 구체적 문제 없음으로 PASS 판정했다. 요청 104의 현재 코드 구조와 권장 작업 순서도 별도로 검수해 PASS 판정했다.

## 6. 미완료 사항과 다음 단계

- 요청 102·103의 사용자 화면 직접 확인은 대기 중이다. 로컬 서버를 새 코드로 재시작해 PID2220이 `http://127.0.0.1:3000/health`에서 HTTP 200을 반환했다. 외부 공개 주소는 없다. 같은 PC 주소에서 새로고침해 확인한다.

- 비밀번호·교사 키·실제 교실 자료는 Git에 포함하지 않는다.
