## 3. 수행 내용과 변경 파일 (Fable 직접 처리)

- 설치: `winget install --id OpenJS.NodeJS.LTS --exact --silent --accept-package-agreements --accept-source-agreements`. 설치 파일 `https://nodejs.org/dist/v24.19.0/node-v24.19.0-x64.msi`, 해시 확인 후 "설치 성공". 사용자가 지시한 설치이므로 Node.js 라이선스(MIT) 동의를 winget 옵션으로 처리했다.
- 결과: `C:\Program Files\nodejs\node.exe` v24.19.0, npm 11.17.0, corepack 0.35.0 포함. 시스템(Machine) PATH에 `C:\Program Files\nodejs\` 등록 확인.
- `교실-시작.cmd`: Node 탐색 순서를 (1) PATH의 node → (2) `%ProgramFiles%\nodejs\node.exe` → (3) Codex 기본 런타임 → (4) Codex cua_node 순으로 변경(정식 설치를 Codex 내장보다 우선). 내용은 PowerShell로 CRLF·UTF-8(BOM 없음)로 저장. 바이트 확인: 1412바이트, CRLF 35, 단독 LF 0, BOM 없음.
- `README.md`: 2절에 정식 설치 사실, 14절에 `corepack pnpm` 사용법 반영.
- `CLAUDE.md` 2절, `메인.md` Git 규칙·현재 상태: 도구 위치 갱신(node 정식 설치, pnpm은 corepack, git은 여전히 Codex 내장).

## 4. 검증 결과 (Fable 직접 검토)

- 새 Node(`C:\Program Files\nodejs\node.exe`)로 `node --test tests/*.test.js` → 12/12 통과.
- 새 Node로 `node scripts/verify-browser.mjs` → 13 checks 통과, errors 빈 배열, 79초.
- `corepack pnpm --version` → 11.19.0 (package.json의 packageManager와 일치, 다운로드 프롬프트 없이 동작).
- `교실-시작.cmd` 탐색 로직: 스크래치 복사본(실행 줄을 `echo RESOLVED=`로 교체)을 두 조건으로 실행. (A) PATH에 nodejs가 없는 현재 세션 → `C:\Program Files\nodejs\node.exe (v24.19.0)` 선택. (B) PATH에 nodejs가 있는 새 터미널 조건 → 동일하게 선택. 두 경우 모두 정식 설치를 사용한다.
- Opus 검증은 사용하지 않았다(환경 설정 소규모 작업, 요청 018 규칙).

## 5. 최종 점검 (Fable)

- 설치 파일 출처(nodejs.org 공식 배포, winget 해시 검증)와 버전(프로젝트 요구 Node 22 이상 충족)을 확인했다.
- 사용자가 직접 할 일은 없다. `교실-시작.cmd`는 그대로 더블클릭하면 된다.

## 6. 미완료 사항과 다음 단계

- 단독 `pnpm` 명령은 등록하지 않았다(`corepack enable`은 Program Files 쓰기 권한 필요). `corepack pnpm <명령>`으로 충분하며 필요 시 추후 등록.
- git은 여전히 시스템에 설치되어 있지 않고 Codex 내장 git을 사용한다. 정식 설치를 원하면 같은 방식(winget `Git.Git`)으로 가능하나 자격 증명 저장소 연동 확인이 필요하므로 사용자 결정 사항으로 남긴다.
- 설치 전에 시작된 터미널·에이전트 세션은 PATH 갱신을 받지 못하므로 전체 경로로 호출한다.
