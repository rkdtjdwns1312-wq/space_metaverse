# 탐사 장치 위치와 스도쿠 정답 확인 (요청428~429)

- 작업 도구/모델: Codex GPT-6, PowerShell, Node.js, Playwright. 최종 검수: 기존 gpt-6-astra 하위 에이전트(세부 ID 자체 조회는 불가), 추가 지적 없음.

## 1. 요청 요약

광장 우주 탐사 그림과 조사 가능한 위치를 맞추고, 스도쿠 정답 확인을 켜기·끄기로 전환한다.

## 2. 계획

원화의 그리기 좌표와 클라이언트·서버의 거리 판정을 비교하고, 스도쿠 입력/확인 흐름을 검사한다.

## 3. 변경 내용·파일

- `shared/config.js`, `server/world.js`, `client/world.js`: 키 큰 탐사 장치 그림의 몸체에 맞춘 조사 영역을 공유 계산한다. 기존 발밑 충돌 원은 유지한다. 그림자와 이름표는 장치 발밑으로 올렸다.
- `client/sudoku-game.js`: 정답 확인 단추를 켜기/끄기로 전환하고, 꺼졌을 때 오답 표시를 숨긴다. 새 판은 꺼진 상태로 시작한다.
- `tests/exploration.test.js`, `scripts/verify-map-equipment.mjs`, `scripts/verify-sudoku.mjs`: 그림 몸체 옆 실제 조사, 멀리서 거부, 스도쿠 켜기·끄기를 확인한다.

## 4. 검증

- 관련 단위 11개 통과, 스도쿠 브라우저 7개 확인 통과, 탐사 장치 포함 지도·장비 브라우저 확인 통과. 브라우저 오류 없음.
- 최종 광장 화면 `.local/428-exploration-world.png`를 직접 열어 그림·그림자·이름표·조사 안내 정렬을 확인했다. `git diff --check` 통과.
- 영향 범위가 광장 상호작용과 오락기 화면에 한정되어 전체 서버 회귀·운영 서버 재시작은 수행하지 않았다.

## 5. 최종 검수

gpt-6-astra로 지정되었던 기존 하위 에이전트가 변경 diff와 검사 결과를 검토했고 추가 문제나 누락을 발견하지 못했다. 에이전트 자체는 세부 모델 ID를 조회할 수 없다고 밝혔다.

## 6. 미완료·다음

운영 중인 교실 서버에는 서버 코드 변경을 적용하려면 안전한 시점의 재시작이 필요하다. 학생 데이터는 변경하지 않았다.

## 7. Git

작업 파일만 선별하여 커밋·`origin/main` 푸시 후 원격 SHA를 비교한다. 기존 미추적 `몬스터 디자인/`은 그대로 보존한다.
