## 1. 요청 요약

`AGENTS.md`, `메인.md`, `2026-09-13_09-42-00_Codex_인수인계_지시서.md`를 읽고 요청 027을 실행한다. 최소 한 학년 동안 같은 교실 코드와 아이들이 만든 내용·소유물을 이어서 사용한다. 기존 STEP 7까지의 기능을 보존하고 다음 작업자가 Claude Code여도 바로 이어받을 수 있게 기록·검증·원격 동기화한다.

## 2. 계획

교실과 수업의 수명을 분리한다. 로컬 파일 저장 계층 → 학생 데이터 직렬화/복원 → 교사 기존 교실 열기 → 학생 비밀번호 → 수업 마치기/연결 만료 → 오류·재시작·기존 기능 검증 순서로 진행한다. 새 유료 서비스나 외부 배포는 하지 않는다. 하위 위임은 파일 저장 계층과 UI에만 한정하고 핵심 권한·데이터 통합과 최종 검수는 Astra가 수행한다.

## 3. 수행 내용과 변경 파일

- `server/store.js`: 코드별 JSON, schemaVersion 1, 임시 파일을 배타적으로 열어 쓰고 fsync한 뒤 rename. 원본 교체 전 실패하면 임시 파일만 정리. 저장 폴더 단일 writer 잠금. 잘못된 JSON/버전/파일명은 거부. 파일 교체 이후 디렉터리 fsync 실패는 이미 확정된 교체를 rollback으로 오인하지 않도록 경고로 분리한다. 디렉터리 fsync 미지원 플랫폼은 파일 fsync와 원자 교체를 사용한다.
- `server/persistent-rooms.js`: `RoomStore`를 상속하는 저장형 클래스. 기본 엔진과 메모리 회귀 테스트는 그대로 유지한다. 저장한 교실 목록과 현재 열린 수업을 분리하고 코드 재사용 충돌을 피한다. 학생 id·아바타·소속·가방·별 파편·비밀번호·최근 기록, 행성/규칙/신청/이름 투표 Map을 복원한다. 위치·현재 맵·접속 토큰·일시 효과·진행 중 거래는 복원하지 않는다.
- 학생 본인 확인: 최초 허용 닉네임 등록 시 숫자 4자리 번호 지정. 무작위 salt + scrypt 해시만 저장. 5회 틀리면 1분 잠금(새 소켓·서버 재시작으로 우회 불가). 교사는 새 번호를 지정하고 기존 접속을 해제할 수 있다. 첫 등록은 교사 감독을 전제로 한다.
- `server/app.js`: `room:list`, `room:open`, `student:pin:set`. 교사 키 검증/시도 제한 또는 현재 교사 세션 권한을 서버에서 확인. 저장 성공 후에만 응답·공개/개인 알림을 전송한다. 저장 실패 시 Map과 세션 참조까지 복구한다. PIN 오입력 및 거래/행성 승인 실패 중 의도한 취소·실패 기록은 별도 `commitOnError`로 저장한다. 교사 연결 만료는 저장된 교실을 삭제하지 않고 수업만 닫는다. 학생이 나가도 멤버십은 유지한다.
- `server/rooms.js`, `server/world.js`, `client/world.js`: `away` 필드를 추가해 수업 밖 학생을 명단에는 남기되 맵에 그리거나 충돌시키지 않는다. 개인별 스냅샷의 비밀 정보 분리 유지.
- `server/index.js`, `scripts/local.mjs`, `.env.example`, `.gitignore`: 실제 실행은 `DATA_DIR`(기본 `data/classes`) 저장 모드. 포트 충돌 시 잠금도 정리. 데이터는 Git/웹에 공개하지 않는다. `교실-시작.cmd`는 변경하지 않았다.
- `server/store-lock.js`, `scripts/unlock-store.mjs`: 강제 종료 후 남은 잠금의 PID가 종료되었음을 확인한 경우에만 명시적 복구 명령으로 해제한다. 실행 중/불명확하면 거절. 자동 해제하지 않는다.
- `client/index.html`, `client/app.js`, `client/style.css`: 학생 비밀번호, 기존 교실 선택/열기, 교사 비밀번호 변경, 수업 마치기, 수업 밖 상태. 비밀번호는 입력 완료 후 비우며 브라우저 저장소에 넣지 않는다.
- `tests/store.test.js`, `tests/persistence.test.js`, `tests/helpers/persistence-child.mjs`: 파일 계층 5개·지속 저장 통합 8개 추가. 테스트 데이터는 임시 폴더만 사용한다.
- `scripts/verify-persistence.mjs`: 실제 브라우저 입장·가입·규칙·지급·구매 후 서버를 새 인스턴스로 재시작해 복원하는 7개 검사. 기존 `verify-browser.mjs`에 합쳐 반복 검증 가능하다.
- `README.md`, `render.yaml`, `메인.md`, `AGENTS.md`: 사용법·저장 범위·백업·잠금 복구·온라인 배포 제한·후속 작업·검증 기준을 정리한다.

위임 기록: Banach(gpt-5.6-luna, low)에 `server/store.js`와 저장 계층 테스트를 맡겼으며, 이어서 겹치지 않는 UI 파일 및 기존 브라우저 PIN 입력 보완을 맡겼다. 본체는 핵심 서버와 저장 통합 테스트·신규 브라우저 테스트를 직접 구현했다. 추가 재위임이나 Claude 전용 모델 규칙 적용은 없었다. 본체 검수에서 저장 후 디렉터리 fsync 처리, 잠금 소유 정보, UI 설명/필수 입력 등을 보완했다.

## 6. 미완료 사항과 다음 단계

사용자가 직접 확인할 순서: `교실-시작.cmd` 실행 → 처음 한 번 교실 만들기 → 학생 번호와 4자리 비밀번호로 입장 → 행성 가입/별 파편 지급/상점 구매 → 수업 마치기 → 서버 창 Ctrl+C → 다시 실행 → 기존 교실 열기 → 같은 코드·닉네임·비밀번호로 복원 확인. 비밀번호를 대화로 보내지 않는다.

이번 기능은 교사 컴퓨터의 파일 저장이며 자동 백업·온라인 영구 저장소·학년 변경/교실 영구 삭제는 미구현이다. 자동 만료는 없지만 실제 1년 운영/디스크 고장 내구성을 실측한 것은 아니다. 정기적으로 정상 종료 후 `data/classes`를 교사 전용 별도 저장장치에 백업해야 한다. `.env`와 데이터는 Git에 포함되지 않는다. 첫 등록 번호 선점 방지를 위해 교사가 학생과 이름을 확인한다. 같은 서버의 전역 교사 키가 모든 교실을 관리한다.

저장 상한: 공개 채팅 50개, 학생별 개인 안내 20개, 사용/거래 기록 각각 100개(교사 화면 최근 20개). 진행 중 거래와 일시 효과는 새 수업에서 취소/해제되고, 이미 사용한 아이템 소비는 유지된다. 컴퓨터 강제 종료 시 남은 잠금은 `node scripts/unlock-store.mjs`로 확인 후 해제하며 수동으로 JSON을 지우지 않는다.

재개 요청 034 이후 다음 작업 번호는 **035**다. 사용자가 이번 저장 기능을 확인한 뒤 STEP 8 나머지(강제 퇴장·이동 잠금·모으기·개별/전체 아이템 지급)를 진행한다. 요청 025 행성 그림 업로드, 레벨/능력/과제 및 온라인 배포 저장소 연결은 이후 단계다. 이전 인수인계 지시서 7절의 '지속 저장 설계 예정'은 이 기록의 구현 내용으로 대체한다.
