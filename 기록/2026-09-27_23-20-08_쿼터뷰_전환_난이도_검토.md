# 쿼터뷰 전환 난이도 검토 (요청292)

- 작업 도구: Codex
- 사용 모델·검수 모델: gpt-6-astra(Astra), 직접 검토

## 1 요청 요약

우주교실을 쿼터뷰로 만들 때 맵·4방향 캐릭터·오브젝트·몬스터 변경의 복잡성과 난이도 질문. 실제 변경 요청은 아님.

## 2 계획

현재 렌더링·좌표·좌우반전·바닥 경계 구조를 확인하고, 그림풍/시점만 개선하는 방식과 좌표 투영까지 바꾸는 방식의 범위를 구분한다.

## 3 수행 내용과 변경 파일

메인과 이 기록만 수정. client/world.js에서 현재 화면좌표는 월드좌표에 카메라 위치/배율을 적용하며, 아바타는 facingX와 원화기준을 곱한 좌우반전. 일부 장면에 y기준 가림순서 존재. shared/floor-geometry.js의 렌더/벽 공유 기하, avatar-size.js의 단계별 크기 확인.

설명안: 기존 서버 좌표·계정·재화·인벤토리·가입/저장 기능을 유지하고 원화 시점과 바닥 접점/가림순서를 정리하는 고정카메라 2D 쿼터뷰가 상대적으로 부담 적음. 수학적 아이소메트릭 투영까지 변경하면 클릭 역변환·스킬방향·미니맵·배치·경계 시각정합의 통합 점검 필요. 4방향은 좌우반전만으로 앞/뒤를 만들 수 없어 새 원화가 필요. 16계보×LV2~5의4단계×4방향=256방향별 모습, 걷기/공격 프레임은 추가. 대칭이면 일부좌우반전 공유가능. 고정된 상점/기둥에4방향그림은 필수아님; 회전배치가 필요한 가구만 방향별그림 고려.

권장 순서: 별도 시험장 또는 광장 시범에서 같은각도의 바닥/기둥1개/캐릭터1종4방향/몬스터1종으로 가림·이동·공격 확인 후 나머지로확대. 이번엔 생성/변경하지 않음.

## 4 검증 결과

현재코드 읽기검토만 진행. 게임코드/이미지/데이터/서버 변경 없음, 실행검사 재수행 불필요. 숫자256은 방향별기본모습 기준이며 최종이미지파일수·애니메이션프레임수를 의미하지 않음.

## 5 최종 점검(검수)

Astra 직접검토. 새게임개발이나3D엔진전환이 필수라는 오해를 피하고, 원화작업과 좌표/판정정합의 난이도를 구분. 전환시간 확정추정/완료주장 없음. 상담/소규모문서로 하위위임 생략.
