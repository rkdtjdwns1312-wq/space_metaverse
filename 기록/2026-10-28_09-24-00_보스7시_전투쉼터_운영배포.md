# 보스 7시·전투·쉼터 변경 운영 배포

- 작업 도구: Codex, Git, SSH, Node.js, Playwright/Edge.
- 작업 모델: Codex 본체(정확한 모델 ID 미제공). 배포 설계·최종 검수: gpt-6-astra(high).

## 1. 요청 요약
사용자가 `홈페이지에 배포까지 부탁해`라고 명시 승인했다. 검증한 5141965의 보스 다음 날 07시·좌우 마우스 전투·쉼터 원화와 오른쪽 화단 제거·사수자리 학생 피해 차단·문 뒤 몬스터 회복을 운영에 반영한다. PC 종료 요청은 없다.

## 2. 계획
SSH 엄격한 호스트키 확인으로 운영 기준 3067214c7ba34d8fa3628f48c439add5c6b1ec8e와 앱/Caddy active를 확인했다. 최신 테스트 브랜치 pull 결과도 일치한다. 고정 커밋의 코드만 별도 릴리스로 준비하고 백업 후 원자적 링크 교체·서비스 재시작·외부 접속 확인을 수행한다.

## 3. 변경 내용·파일
게임 코드 변경 없이 승인과 배포 범위를 이 기록·메인에 추가한다. 비공개 `.local/prepare-oct28-release.mjs`가 raw Git blob 델타 및 전체 런타임 해시 목록을 만든다. `.local/deploy-oct28-release.sh`는 이전 릴리스를 복사하고 코드만 덮으며 의존성 일치를 확인한다. 자료·비밀번호·조합 설정을 새로 만들거나 GitHub에서 가져오지 않는다.

## 4. 검증
게임 검사는 직전 동일 코드 증거 재사용: 전체 서버1,279 중1,277 PASS, Windows 임시파일 EPERM 2건 포함 파일 재검사25/25 PASS, 기본 화면91·마우스/공원 실화면·Astra 검수 PASS. 배포에서는 전체 런타임 해시·백업 체크섬·설정/자료 보존·health/비공개 조합26·HTTPS/WSS·새 공개파일 해시·입장 화면을 확인한다. 실제 결과는 최종 답변과 비공개 배포 로그로 확인한다.

## 5. 최종 검수
gpt-6-astra(high): 준비된 세 스크립트와 승인 기록의 기준 SHA·파일 해시·백업·설정 보존·원자적 전환·실패 복귀·외부 검증 경로 검수 PASS, 배포 차단 사항 없음. 실제 운영 검증 결과와 SHA는 최종 응답/비공개 완료 로그에 남긴다. 게임 코드를 바꾸지 않아 이미 통과한 검사를 중복하지 않는다.

## 6. 미완료·다음
성공 확인 전에는 배포 완료로 간주하지 않는다. 새 코드가 기존 보스 대기시각을 07시로 변환하므로 시작 뒤 학급 파일 해시가 달라질 수 있으며 무조건 동일하다고 주장하지 않는다. 배포 직전 백업과 설정 체크섬을 보존한다. 실제 계정으로 로그인·보상 지급·교실 변경 검사를 하지 않는다.

## 7. Git
문서 기록만 추가하여 테스트 브랜치와 main을 같은 검증 계보로 fast-forward push한다. 원격 SHA를 실제 확인하고 정확한 커밋을 운영 릴리스로 사용한다. 비밀값·`.local`·학급 데이터는 커밋하지 않는다. 배포 성공 문구만을 위한 추가 문서 커밋은 하지 않는다.
