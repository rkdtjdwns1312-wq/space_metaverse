## 1. 요청 요약

- 사용자(2026-09-12 09:3x KST): 행성마다 넣고 싶은 반응은 크게 없음. 아이들이 움직이는 맵은 우주 공간이고 행성은 하나의 부서. 아이들은 교실에서 맡을 역할에 따라 행성에 가입하고, 가입된 곳만 들어갈 수 있음. 행성을 눌렀을 때 소속된 아이들에게만 '입장' 버튼이 생기고, '행성의 규칙 확인하기'를 누르면 행성에서 정한 교실 규칙(예: 줄 안 서면 경고)이 나오면 좋겠음.
- 원래 요구사항(요청 012 기록): 부서행성은 아지트 개념, 한 아바타는 한 부서만 가입, 자유 가입/탈퇴, 가입자만 출입. 근처 오브젝트에 E키 안내와 상호작용 버튼, 모바일 터치 버튼. 권한은 서버 검증.
- **추가 지시(2026-09-12 09:5x KST, 구현 도중)**: 일기·독서·교과·청소행성은 예시 이름일 뿐이다. 각 행성은 그런 느낌의 역할 행성이고, 이름은 아이들이 다수결로 수정할 수 있다. 아이들이 만들어내는 교실의 역할이 곧 행성이며 개수는 7개도 10개도 될 수 있다. 아이들이 직접 만들 수 있게 하고, 선생님은 행성을 만들 때 승인만 한다. 행성을 만들 위치는 우주 맵에서 아이들이 직접 지정한다.

## 2. 계획 (Fable)

- 1차 설계(고정 행성 4개)로 서버·화면 에이전트를 시작한 직후 추가 지시를 받아 **동적 행성 설계로 변경**했다. 1차 구현 중 살아남는 부분: 내부 맵, 가입/탈퇴/입장/나가기, 규칙, 상호작용 프롬프트, 대화상자 골격. 바뀌는 부분: 행성이 설정 상수가 아니라 방별 데이터가 되고, 신청·승인·위치 지정·이름 투표가 추가된다.
- 설계 결정(최종):
  - 행성은 방(교실)마다 동적으로 만들어지는 데이터. 방을 만들 때는 행성이 없고 가운데 '모여라, 빛나는 별'만 있다. 선생님이 교실 만들기에서 '예시 행성 4개로 시작'을 켜면 독서·일기·청소·교과 예시가 미리 놓인다(기본 꺼짐).
  - 만들기: 학생이 '행성 만들기' → 지도에서 자리를 클릭 → 이름(2~10자)·소개(40자 이내)·색(팔레트 8색) 입력 → 신청. 서버가 경계·겹침(별·기존 행성·대기 중 신청과 간격 30px 이상)·금지어·개수 한도(방당 12개, 대기 6개, 학생당 대기 1개)를 검사. 선생님이 '승인' 또는 '돌려보내기'. 승인되면 신청한 학생이 첫 멤버가 된다. 선생님이 직접 만들면 즉시 생성. 선생님은 행성을 없앨 수도 있다(안에 있는 사람은 광장으로, 소속은 해제).
  - 이름 바꾸기: 소속 학생이 새 이름을 제안하면 소속 학생 전원이 찬성/반대 투표(공개 투표, 바꿀 수 있음). 찬성이 소속 인원의 과반(⌊n/2⌋+1)이 되면 즉시 변경, 반대가 과반이거나 통과가 불가능해지면 부결. 행성마다 한 번에 하나의 투표. 선생님은 투표 없이 바로 바꿀 수 있다. 소속 1명이면 제안이 곧 통과.
  - 행성 내부 맵(`planet:<id>`, 광장과 같은 1200×760, id는 UUID라 이름을 바꿔도 유지)에 규칙 게시판(충돌)과 광장으로 나가는 문(통과 가능). 같은 맵에 있는 사람만 서로 보임.
  - 학생은 한 행성에만 소속. 다른 행성 가입은 자동 옮기기('옮겨오기'). 탈퇴 가능. 선생님은 가입 없이 모든 행성 입장.
  - 입장 조건은 서버 검사: 광장에 있음 → 소속 또는 교사 → 행성 가까이(행성 반지름 + 소행성 반지름 + 40px). 나가기는 내부 어디서든 가능.
  - 규칙: 새 행성은 기본 규칙 '서로 존중하고 친절하게 말해요' 한 줄로 시작. 선생님이 1~8줄·40자로 수정. 예시 행성은 각자 예시 규칙(청소행성 '줄을 서지 않으면 경고를 받아요' 등).
  - 신청·승인·거절·삭제·가입·탈퇴·옮기기·이름 투표 시작·결과·규칙 변경은 시스템 채팅 안내. 입장·나가기는 안내 없음.
  - 위치 브로드캐스트는 전원에게 보내고 화면이 mapId로 걸러 그림. 대기 중 신청은 지도에 점선 원으로 표시.
- 작업 분할: Fable이 `shared/config.js` 계약 작성 → Sonnet A(서버·테스트)와 Sonnet B(화면·README) 병렬 → 추가 지시 반영을 같은 에이전트에 이어서 지시(맥락 유지) → Sonnet C(브라우저 통합 검사·연동 수정) → Opus 검증 → Fable 최종 점검·커밋.
