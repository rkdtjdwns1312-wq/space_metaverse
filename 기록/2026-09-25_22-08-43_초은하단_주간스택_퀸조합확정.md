# 초은하단 주간 스택 · 에일리언 퀸 조합 확정

작업 도구: Codex
사용 모델: gpt-6-astra (Astra), gpt-6-luna low (Mendel)
최종 검수 모델: gpt-6-astra (본체 직접)

## 1. 요청 요약
요청209. 초은하단은 보유 중 매주 스택1을 쌓고, 보유효과 사용에서 스택1=별 파편4 또는 스택2=별 카드1을 선택한다. 퀸의 조합 재료 중 이름/레벨이 불일치하던 항목은 사용자 답변으로 확정됐다. 실제 조합 내용은 이 문서와 공개 코드에 적지 않는다.

## 2. 계획
기존 비활성 자동 보상 선택 방식을 없애고 주간 적립과 수동 교환을 분리한다. 스택과 요청 식별자를 지속 저장하고, 재시도/저장 실패/카드 매도·재구매를 검사한다. 별도로 비공개 퀸 조합을 등록한다.

## 3. 수행 내용과 변경 파일
- server/lv4-item-effects.js: 새 상태 stacks/nextStackAt/claimIds, 기존 teacher receipts/priorityUntil 보존. 구형 rewardMode/nextRewardAt 저장을 읽어 스택0으로 변환한다. 당시 보유 보상은 비활성이라 가상의 과거 보상은 만들지 않는다.
- 주간 적립: 보유 시점부터7일마다1, 여러 장이어도 소지자별1주기. 오프라인/서버 종료 기간을 다음 정산에 합산한다. 자동으로 재화나 아이템을 주지 않는다.
- 보유효과: LV4 이상이고 초은하단 보유/기존 사용조건을 만족해야 한다. 1스택4파편 또는2스택별카드1, 원본 카드는 유지. 일반 아이템 사용(소모 후 원하는 금별2장)과 분리했다. 보유효과의 별 카드1장은 기존 무작위 별 카드다.
- 마지막 카드를 잃으면 적립 정지, 기존 스택은 개인에게 보존하고 양도하지 않는다. 다시 소지하면 새7일 주기로 적립한다. 서버 action의 저장 작업 시작에서 먼저 기간을 정산해 매도/거래 직전에 얻은 주간 스택을 잃지 않는다.
- 교환은 복사본에서 검증/소비 후 반영하고 파일 저장과 묶는다. 보상 가방·지갑 상한 또는 스택부족/저장실패 시 전체 취소. 기존 해/개기일식 사용료도 적용. 동일 requestId 재전송은 성공한 보상을 다시 주지 않고 현재 스택을 반환한다. 최근600개 식별자를 저장한다.
- server/app.js: lv4:holding:use, 저장되는 lv4:info, 주간 스택 정기 정산. 이전 보상 방식 선택 API 제거. 공개 스냅샷에 다른 학생의 스택을 추가하지 않았다.
- client/app.js + client/lv4-item-ui.js: 가방의 보유효과 사용 버튼, 현재 스택/다음 적립일, 두 교환 버튼, 부족 시 비활성, 통신 중 중복 클릭 차단/실패 시 동일 식별자로 재시도. 기존 소모형 초은하단 창도 유지한다.
- shared/lv4-items.js 설명 갱신. data/crafting-recipes.json에 퀸 등록(비공개, Git 제외). LV4는7종/대체 조합 포함8변형. 실제 조합 성공·수수료1·재료소모를 비공개 로컬 검사로 확인했다.
- 위임: Luna Mendel은 UI 파일과 별도 모듈 테스트를 순차 담당. 부모가 엔진·API·가방 연결·지속 저장/브라우저 검사·비공개 조합·검수 담당. 요청한 gpt-5.6-luna가 제공되지 않아 기존 합의대로 gpt-6-luna low 사용.

## 4. 검증 결과
- 전체 서버478/478, 기존/지속저장 브라우저91, LV4 브라우저12 통과. LV4 모듈15 및 저장 통합2 포함.
- 시간 주입으로3주 누적→별 카드1장→파편4개, 잔여 스택, 카드 유지, 중복 요청, 파일 실패 후 동일 요청 재시도, 재시작 복원, 매도/재구매 주기를 확인했다.
- 기존 구형 LV4 저장 변환과 교사 확인 기록 보존을 별도로 검사했다. 낮은 레벨·미보유·사용금지·가방/지갑 가득 참은 원복한다.
- 실제 브라우저 가방 버튼, 스택3→2→0, 두 보상 지급, 카드 수량 유지, 0스택 버튼 비활성, 재접속,320px 가로 넘침을 검증했다. 화면 .local/209-holding-mobile.png 육안 확인.
- UI 검토에서 누락된 부족 스택 버튼 갱신 함수를 부모가 추가했다. 브라우저 검사에서 이미 선택된 가방 칸을 다시 눌러 해제하던 테스트 동작을 고쳐 현재 선택 여부를 확인했다.
- 비공개 자료와 실제 학급을 시험 대상으로 쓰지 않았다. 운영 재시작 전후4개 학급 JSON SHA256 해시 동일, health200, stderr 빈 상태 확인.

## 5. 최종 점검(검수)
Astra 직접 검수 완료. 요청한 수동 선택, 기존 소모 효과와 분리, 서버 결정 스택/보상, 요청 재전송 및 파일 실패 원복, 비공개 조합, 모바일 표시, 이전 저장 호환을 확인했다. 주간 스택에 실제1주를 기다리는 대신 주입한 서버 시각으로 경계를 검증했다.

## 6. 미완료 사항과 다음 단계
- 이번에 재질문한 보유효과와 퀸 재료 결정은 모두 반영 완료.
- 퀸의 상점 구매/되팔기 가격만 기존 미정 재료 가격에 의존한다. 임의 가격을 만들지 않고 준비 중 유지. 조합/지급/사용은 가능하다. 관련 기존 LV3·안드로이드 가격 미정 기록 참조.
- 학생 시간 제한 테스트 해제는 그대로, 나중에 놓친 작업을 요청하면07~21시 복원을 안내한다.
- 비공개 조합 파일과 학급 자료는 Git으로 이동하지 않는다. 교실 PC로 이전할 때 별도 비공개 복사한다.
