# 천칭자리 주간 능력 Lv2~5

- 작업 도구: Codex desktop / PowerShell / Node.js 24.
- 구현: Codex. 최종 읽기 전용 검수 요청 모델: gpt-6-astra(high). 검수 응답에는 GPT-6로 표시되며 세부 모델 ID는 응답 자체에 노출되지 않음.
- 한국 시간: 2026-10-20.

## 1. 요청 요약

천칭자리 주간 능력을 Lv2 주차별 경험치, Lv3 주사위 2개의 차이만큼 별 파편, Lv4 4회 주사위 카드 판정으로 만들고, 후속 요청에 따라 Lv5는 같은 카드 판정을 주사위 **3회**로 적용한다.

## 2. 계획과 결정

Lv2 경험치는 기존 교사 능력 확인 기둥에서 주차를 고른 후 1주차 0, 2~3주차 1, 4~5주차 2를 지급한다. Lv4/5에서 같은 눈이 하나라도 있으면 뽑기 카드 1장, 모두 다른 눈이면 별 카드 1장을 준다. 뽑기 카드는 기존 카드 더미를 사용하되 별도 아이템으로 만들어 달토끼의 일일 제한과 구분한다. 저장 실패·가방 부족 때 결과를 골라 재추첨하지 못하도록 굴리기 전에 두 카드의 수납 가능 여부를 검사한다.

## 3. 변경 내용과 파일

`shared/constellation-weekly-abilities.js`, `server/constellation-weekly-abilities.js`, `shared/constellation-abilities.js`, `shared/constellation-stages.js`에 단계별 규칙·결과 저장 검증·Lv5 설명을 넣었다. `server/app.js`, `client/app.js`, `shared/config.js`, 새 `client/assets/cards/silver-draw-card.svg`로 뽑기 카드의 실제 지급·사용·재접속 경로를 연결했다. `client/constellation-ability-ui.js`와 `client/style.css`에는 2·3·4개 주사위 눈을 함께 보여준다. 관련 테스트와 실제 브라우저 검사에 Lv5를 포함했다. 전체 회귀 검사 중 발견한 교양 책장 재열기 경합은 `client/culture-library.js`에서 바로잡았다.

## 4. 검증

전체 서버 검사 `node --test --test-concurrency=1 tests/*.test.js` **1,061/1,061 통과**. 기본 브라우저 검사 `node scripts/verify-browser.mjs` **85개 흐름, 오류 0**. 주간 능력 브라우저 검사 `node scripts/verify-constellation-weekly.mjs` **13개 흐름, 오류 0**이며 Lv5 화면에서 주사위 3개와 별 카드 실제 지급을 확인했다. 관련 46/46 및 `git diff --check` 통과. 샌드박스의 임시 로컬 WebSocket 접속 차단으로 첫 검사에 접속 실패가 나서, 승인된 비샌드박스 로컬 검사로 다시 실행해 통과했다. 이후 예전 Lv5 능력 동일성 테스트 1건을 새 천칭 예외에 맞게 고쳐 전체 검사에서 통과했다.

## 5. 최종 검수

지정한 Astra 검수는 추첨 전 가방 용량 검사와 이전 테스트 갱신을 제안했고 반영했다. Lv5 추가 후 주사위 횟수·중복 판정·저장 검증·화면 검사에서 P0~P2 문제를 찾지 못했다. 마지막 Lv5 전용 원화 테스트 변경도 P0~P2 없음으로 재확인했다. 실제 브라우저 화면 PNG도 확인했다.

## 6. 미완료 및 다음 작업

주간 능력은 16종 중 7종 구현, 다른 9종은 사용자가 효과를 정하면 차례로 연결한다. 로컬 교실의 학급 저장 파일 1개를 비공개 `.local`에 백업하고 SHA-256 일치 확인 후 기존 서버를 새 코드로 재시작했다. 새 서버의 `/health`는 `ok=true`, `persistent=true`로 응답했다. 외부 공개는 이번 작업 범위가 아니다.

## 7. Git

이 작업 파일만 선별해 커밋·`origin/main`에 push하고 실제 원격 SHA를 확인한다. 기존 사용자 HWP 삭제 상태와 미추적 몬스터 디자인은 손대지 않고, `.env`·`.local`·`data/classes`와 비밀 정보는 Git에 넣지 않는다.
