# 요청427 · 관리자 교실 삭제와 활성 교실 한도

- 작업 도구: Codex GPT-6, PowerShell, Node.js, Playwright. 최종 검수는 도구 호출에서 `gpt-6-astra`로 지정했으나 검수 에이전트 자체는 세부 모델 ID를 확인하지 못했다고 보고함.

## 1. 요청 요약

관리자가 만든 교실을 삭제할 수 있게 하고, 활성 교실 한도 확대 방법과 서버 부담을 확인. 후속 지시로 첫 화면 오른쪽 아래에 관리자 입장 버튼을 두고 관리자 비밀번호를 선생님 키와 분리.

## 2. 계획

관리자 전용 삭제와 코드 재입력, 접속자 퇴장, 저장 실패 복구를 연결. 활성 교실 한도는 기본값을 유지하면서 설정 가능하게 하고 실제 하드 제한을 문서화.

## 3. 변경 내용·파일

- `client/admin.html`, `client/admin.css`, `client/admin.js`: 교실별 삭제 버튼과 코드 입력 확인창, 오류 표시, 연결 해제 시 모달 닫기.
- `client/index.html`, `client/app.js`, `client/readability.css`: 관리자 입장을 선생님 탭 밖의 첫 화면 오른쪽 아래 독립 버튼으로 변경.
- `server/app.js`, `server/persistent-rooms.js`, `server/store.js`: 관리자 권한·정확한 교실 코드 확인, 세션 해제·퇴장, 저장 파일 제거. 제거 실패 시 메모리·소켓 상태 복원.
- `server/app.js`, `server/admin-password.js`, `server/index.js`, `scripts/local-state.mjs`, `scripts/local.mjs`: 별도의 `ADMIN_PASSWORD`로 관리자 인증. 미설정·공개 예시값은 서버 시작 거부, API 기본값은 임의 비밀번호. 기존 `TEACHER_KEY`는 선생님 코드 검증에 유지. 요청한 실제 비밀번호는 Git에서 제외되는 로컬 `.env`에만 설정.
- `server/rooms.js`, `server/index.js`, `scripts/local-state.mjs`, `scripts/local.mjs`, `.env.example`: `MAX_ACTIVE_ROOMS` 기본 10, 허용 1~40. 저장된 교실 발급은 활성 교실 한도와 분리.
- `README.md`: 영구 삭제와 한도 설정·400개 접속 연결 한계 안내.
- `tests/admin-delete.test.js`, `tests/teacher-access.test.js`, `scripts/verify-admin-ui.mjs`: 삭제 권한·실패 복구·재시작·한도 경계, 관리자 비밀번호 분리, 데스크톱/모바일 확인창 조작.

## 4. 검증

- `node --test --test-concurrency=1 tests/*.test.js`: 최종 734/734 통과.
- `node scripts/verify-browser.mjs`: 기본 브라우저 검사 통과, 오류 0.
- `node scripts/verify-admin-ui.mjs`: 1440/390 화면, 생성·취소·오입력 거부·삭제·연결 해제 후 재입장, 홈 화면 오른쪽 아래 관리자 버튼과 링크 통과.
- 실제 로컬 `.env`에서 관리자 비밀번호가 별도로 설정되어 있고 선생님 키와 다른지 확인(비밀번호 출력 없음).
- `git diff --check`: 공백 오류 없음.

## 5. 최종 검수

최초 검수에서 삭제 모달을 연 상태로 연결이 끊어지면 재로그인이 막히는 문제를 찾아 수정. 후속 검수에서 관리자 비밀번호 누락 시 선생님 키로 대체되는 경로와 공개 예시 비밀번호 허용 문제를 찾아 모두 차단. `gpt-6-astra` 지정 최종 재검수에서 추가 문제 없음 판정. 에이전트의 세부 모델 ID 자체 확인은 불가하므로 모델 지정은 호출 기록 기준.

## 6. 미완료·다음

실제 학생 교실은 삭제하지 않았음. 로컬 서버에서 기존 교실 하나가 열려 있어 연결을 끊는 재시작은 보류하고 사용자에게 시점을 확인 중. 새 관리자 인증은 그 서버 재시작 뒤 적용됨. 20개 이상 동시 운영 부하 검사는 실제 학생 수·호스팅 사양이 정해진 뒤 필요. 현재 접속 연결 총량 400개, 게임 계산은 50ms 간격이며 위치/몬스터 방송은 약 100ms 간격. 활성 교실·인원 증가에 따라 CPU·메모리·네트워크·저장 작업이 늘어남. 자동 백업·확장형 데이터베이스는 아직 없음.

## 7. Git

기존 사용자 미추적 폴더 `몬스터 디자인/`과 비공개 교실 자료는 제외. 변경 파일만 선별 커밋·푸시하고 원격 SHA를 확인한다. 실제 결과는 최종 응답에 기재.
