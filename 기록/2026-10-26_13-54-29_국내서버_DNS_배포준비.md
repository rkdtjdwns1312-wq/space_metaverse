# 국내 서버·도메인 연결과 새 교실 배포 준비

- 작업 도구: Codex, PowerShell/OpenSSH, 로그인된 브라우저
- 사용 모델: 본체 세션 기본 모델, 복잡한 배포 설계·구현 gpt-6-astra
- 최종 검수 모델: gpt-6-astra

## 1. 요청 요약

사용자가 구매한 국내 iwinv 2GB 서버에 우주 교실을 배포하고 구매한 도메인을 연결한다. 기존 G9N387 이전 요청은 취소하고 완전히 새 교실로 시작한다. 관리 PC는 두 대지만 현재 PC의 SSH 키·IP부터 등록하고 TCP 80·443 공개 및 도메인 연결을 진행하도록 명시적으로 승인했다.

## 2. 계획

기존 자료를 보존하고 접근 범위를 제한한다. 서버 공개키를 대조한 뒤 키 기반 연결, 별도 운영 계정·새 비공개 설정·빈 저장소·Caddy HTTPS·백업 순으로 배포한다. 비밀번호 입력은 사용자에게 맡긴다.

## 3. 변경 내용·파일

- iwinv 방화벽: SSH는 승인한 현재 PC 공인 IP만, TCP 80·443은 웹 접속에 공개. TCP 3000은 공개하지 않았다. 두 번째 PC는 아직 추가하지 않았다.
- HostingKR: `woozooclass.kr`의 `@` A 레코드 1개를 새 서버로 설정(TTL 180). 네임서버·자동연장·연락처는 변경하지 않았다.
- `.local/`에 이 PC 전용 SSH 키, 서버 known-hosts와 비밀번호를 저장하지 않는 일회용 키 등록 CMD를 준비했다. 사용자에게 직접 실행하도록 인계했으며 이 파일들은 Git 대상이 아니다.
- `deploy/`: Ubuntu 운영 안내, Caddy와 systemd 설정, 비공개 환경 생성기, 중지된 저장소 잠금 점검, 로컬 백업 및 일일 타이머, 호스트 검사. `tests/deployment.test.js`: 신규 설정·잠금·실제 임시 저장소 앱 부팅 검사.
- 기존 앱 코드·학급 파일·교사키와 기존 서버는 변경하지 않았다.

## 4. 검증

- 방화벽 UI에서 승인한 3개 인바운드 규칙 저장 확인.
- DNS UI A 레코드 저장 확인, 권한 DNS ns1/ns2에서 새 서버 주소 응답 확인. PC 기본 DNS에는 이전 파킹 주소 캐시가 남아 있어 전파 완료로 단정하지 않는다. AAAA 주소는 조회되지 않았다.
- 사용자가 로그인한 iwinv VNC에서 서버 SSH Ed25519 지문을 읽고 SSH가 제시한 값과 일치 확인 후 known-hosts에 저장했다. 사전 검증이 없는 최초 신뢰 응답은 자동 승인 검토에서 거부되어 전송되지 않았고, 신뢰할 수 있는 VNC 지문을 확인한 후 처리했다.
- 공개키만 사용하는 SSH 접속은 인증 거부: 공개키의 서버 등록을 아직 사용자가 완료하지 않았으므로 예상된 대기 상태다. 비밀번호를 수집하거나 저장하지 않았다.
- 새 임시 DATA_DIR의 실제 앱 부팅을 포함한 배포 검사 4건 통과. Bash/Node 문법 검사 통과. Ubuntu systemd·Caddy·실제 백업 및 복구 검사는 미실행이다.
- 앱 코드 기준은 `440dd6b`: 직전 정원 변경의 전체 서버 1,177·기본 화면91·정원 화면5와 후속 진화 변경43·화면12의 기존 검증 증거를 재사용한다. 이번 준비만으로 운영 배포 검증을 완료한 것은 아니다.

## 5. 최종 검수

gpt-6-astra 최종 검수 완료: 배포 구성의 보안·저장소 잠금·백업 실패 시 재시작·비밀값 생성 및 검사 범위 확인. 준비 파일은 PASS이며 실제 서버 확인이 필요한 항목은 준비 완료와 분리해서 보고한다.

## 6. 미완료·다음 작업

- 사용자 일회용 키 등록 완료 후 BatchMode SSH 인증을 확인해야 한다. 호스트키 확인을 생략하지 않는다.
- 아직 서버에 앱/Node/Caddy 설치, 인증서 발급, 교실 생성, 서비스·백업 타이머 활성화를 하지 않았다. 웹 포트 개방과 DNS 저장은 교실 개통과 다르다.
- 서버의 아웃바운드 규칙이 없는 경우의 실제 송신 동작을 설치 전 확인한다. 전체 송신 허용은 무조건 추가하지 않는다.
- 설치 후 HTTPS·WebSocket·비공개 경로 차단·빈 새 교실 저장/재시작·백업/복구를 검증한다. 초기 활성 교실 한도는 1이며 35명 성능은 실측 전 보장하지 않는다.
- 두 번째 PC는 나중에 별도 공개키와 접속 IP를 등록한다. 학생·교사 웹 입장에는 SSH 키가 필요 없다.
- 로컬 백업은 같은 디스크 손실에 대비할 수 없다. 외부 암호화 백업은 아직 미구성이다. 공개 기본 조합법만 사용하며 별도 비공개 조합법은 복사하지 않는다.
- 프록시 뒤 교사/관리자 실패 로그인 제한이 주소 하나로 합산되는 기존 동작을 보수적으로 유지했다. 다중 교실 확대 전 별도 개선이 필요하다.

## 7. Git

배포 준비 파일·관련 검사·메인과 본 기록만 선별 커밋하고 `HEAD:main`으로 저장한다. 비공개 파일·스크린샷·학생 자료는 포함하지 않는다. push 결과와 실제 원격 SHA 일치는 실행 후 최종 답변에서 확인하며 사전에 성공으로 기록하지 않는다.
